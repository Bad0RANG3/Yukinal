# MoE 路由与推理连续验收 · 2026-10-18

本轮验证应用层协调路由、模型参数、上下文隔离、流式正文与工具循环；不将供应商内部神经 MoE、原生界面、目标机器或长期压力测试推定为通过。全程未使用 Computer Use。

## 发现与修复

- 角色只指定供应商时，原实现继承主会话模型名。现在使用所选供应商默认模型；显式供应商和模型仍优先。
- 角色仅更换模型时，原实现继续继承父模型推理强度，可能被子任务准入拒绝。现在仅同模型或完整继承保留推理强度。
- `check:ai` 纳入原有推理强度测试，以及新增的真实 worker 路由、SDK 流式工具轮和持久恢复组合回归。

## 可复验入口与边界

安装 Agent 依赖后运行 `pnpm check:ai`。新增的 `test_agent_moe_routing`、`test_agent_reasoning_loop` 与原有 `test_reasoning_effort` 可单独重复运行；均使用临时数据和本地夹具，无真实额度或远程操作。

真实测试使用产品 PythonSidecar RPC、ProviderStore、ModelFactory、DeepSeekChatModel 和生产 DesktopCredentialStore，反向主机接口仅提供指定供应商凭据及空测试上下文；未注册目标操作工具。原数据库只读，密钥只在内存传递，测试数据自动清理。脱敏 JSON、逐轮日志和趋势 HTML 留在本机 `target/ai-continuous-20261018/`，不提交原始私有记录。

线上已验证 deepseek-flash 的 low 推理参数；none/low/high/max 序列化及不支持组合由本地回归覆盖。high/max 未分别进行真实请求。服务端对简单任务可能不输出私有推理；非空时验证回传，不把缺省空值判为丢失。

此 MoE 指应用层角色分派和请求模型绑定，无法由 API 验证供应商内部专家门控；不同请求模型名也不证明底层权重不同。真实调用未走原生 stdio/WebView，慢消费者、断管和 UI 显示仍是独立验收范围。
