# 目标架构与施工交接

> 状态：目标架构与施工交接。本工作树已有第一轮跨层实现和自动测试，但核心的真实 Provider/MCP/SSH 工作流、三平台原生文件操作和安装版 GUI 验收仍未完成。安装包与回归测试的历史证据见[交付与发布](./release.md)。接手 agent 应先核实下面的施工快照，再补齐缺口；不要把代码存在或本地测试通过写成用户目标已交付。

## 目标与角色

用户给 Yukinal 一个目标，例如“检查预发布服务器的 502，修复配置并验证服务恢复”。AI 应理解目标、发现已配置的工具、调用添加到 Yukinal 的服务器所需的命令或配置能力、读取结果、处理失败并给出可复核的结论。对明确授权范围内的日常操作，用户不必把每一步翻译成命令。危险操作按目标环境和权限规则停下来等待批准。

服务器工作区供运维工程师观察主机、服务、日志、文件和任务进度；它也是人工介入的入口。文件工作区是本机与远端之间的直接传输界面：Windows、macOS、Linux 用户能从系统文件管理器拖入文件上传，预览本机或远端文件，选择文件下载，也能通过拖放完成远端到本机的传输。传输不需要经过模型或聊天附件。

这里的“服务器”指用户添加并通过 SSH 身份核验的目标主机；“MCP 服务器”指提供工具的本地进程或网络端点。二者不能因为名称相同就互相取得权限。“工作区”在本文指运维界面；项目记录仅用于组织服务器、仓库和 Provider，不构成远端权限。

## 一次任务的目标调用链

```text
用户目标 + 选定服务器/环境 + 委托范围
  → Agent 获取有时间和来源的状态、内建工具与已启用的 MCP 目录
  → Agent 形成可见任务步骤（读取、变更、验证和失败处理）
  → 权限引擎对每次具体工具输入、目标和委托范围作决定
  → Rust 宿主再次核验目标、任务/计划、批准票据和参数
  → SSH 命令 / SFTP / 内建运维能力，或受控 MCP 调用
  → 有界结果和证据返回 Agent → 继续、重计划或交还用户
  → 工作区展示当前状态、实际操作、验证结果和活动记录

系统文件管理器 ↔ 本机文件选择/拖放 ↔ Rust 文件传输模块 ↔ SFTP ↔ 目标服务器
                                      ↘ 进度、冲突、预览、取消和活动记录
```

**硬约束：**模型不持有 SSH 凭据或连接；sidecar 不直接执行远端命令。终端仍是用户主动输入的人工入口。Agent 的命令调用必须通过工具注册、权限决策和宿主执行链；不能把聊天文本注入终端，也不能借“手动传输”入口绕开 Agent 的授权规则。手动传输是用户直接发起的另一条宿主路径。

## 模块及接口要求

### 1. 目标和工具目录

- 一次任务先绑定稳定的 `serverId`、环境、允许的工作范围与有效期。界面明确显示真实主机、用户、端口和已核验的主机身份；模糊名称不得直接变成可执行目标。工具目录同时呈现内建工具和用户已启用的 MCP 工具，并区分来源、可用状态与能力。
- Agent 可以选择内建结构化工具、受控命令工具或 MCP 工具。工具不可用、能力不匹配或目标断连时，明确说明并请求补充配置或重新规划，不能假装已经执行。
- MCP 描述、schema 和自报风险是外部数据。MCP 进程/端点不能因为返回了 `serverId` 就获得 SSH 权限；实际作用到外部系统的工具需要可核验的目标映射与风险配置。无法确认目标和副作用时，默认要求逐次批准，且审计显示 MCP 来源。

### 2. Agent 命令执行接口

- 增加一个明确命名的远端命令工具，例如 `server.exec`。输入至少包括命令正文、预期目的、超时和输出上限；可选工作目录和非敏感环境变量必须有宿主校验。目标从已解析的任务 `serverId` 传入，不由模型自填 host/port/凭据。SSH exec 本身传递命令字符串，不能宣称将字符串拆成 `argv` 就消除了远端 shell 的解释风险。
- 宿主在发送前复核：服务器记录和环境仍匹配、主机身份可信、任务及有效计划步骤存在、命令命中精确输入批准或有效的任务级命令授权、超时/输出限额有效。执行结果包含退出码、stdout/stderr 的截断状态、耗时、取消或连接中断状态。非零退出与“请求已发出但结果未知”不能显示为成功。
- 任意 shell 命令默认按高风险处理；正则关键字扫描只能上调风险，不能证明命令只读。用户可对**单个开发/预发布任务**一次性授予“在这台服务器上执行高风险命令”的权限，票据绑定 `taskId`、`serverId`、环境、有效期、命令次数/总时长/输出预算与用户身份。宿主在每次执行前重验这些约束并记录实际命令；票据不能用于生产、未知环境、其他服务器或被判为关键危险的调用。默认仍逐条批准，不可由 Agent 自己生成委托票据。界面在授予前明确解释此权限允许 AI 连续执行事先未知的命令。
- 对可反复使用的操作再提供由用户配置、限定可执行程序/参数/目录/目标的命令模板；模板的输入经宿主校验后才可按其声明的较低风险运行。内建结构化工具继续用于可以精确建模的操作。
- 读取类工具在允许范围内自动执行。开发/预发布服务器的普通结构化变更可按显式任务委托自动执行；获任务级命令授权后，高风险命令也可在该任务内连续执行并验证。未知目标、生产变更和关键危险操作仍等待与具体输入绑定的批准；扩大目标、预算、操作类别或有效期时重新授权。
- 计划和执行记录由 Agent 自动生成并在工作区可见，不能要求用户先手工填写内部 `ChangePlan` 字段。现有持久计划守卫继续在宿主起作用；如需简化用户流程，应由任务编排生成合法计划、步骤与证据绑定，不能从宿主删除守卫。

### 3. 运维可视化工作区

- 服务器概览展示连接状态、最后采集时间、数据来源、刷新中/过期/失败、CPU/内存/磁盘、服务/容器与关键日志入口。无数据按“未知/不可用”显示，不能用旧快照冒充实时数据。多服务器切换后每条数据必须保留正确 `serverId`。
- 同屏能看到任务目标、正在调用的工具、目标服务器、批准等待、步骤结果、验证结论和失败后的下一步。操作者可从状态异常跳到相应日志、文件、服务或任务记录。活动记录应可按服务器和任务追溯，但不存完整敏感正文。
- 工作区展示是观测和人工接管能力，不承担模型执行或权限判定。后台采集的节流、断连和恢复不能让 UI 阻塞，也不能触发未授权的变更。

### 4. 本机与远端文件传输

文件传输模块的对外接口应围绕少量动作：**选择来源和目的地、启动、查询/订阅进度、取消、处理冲突、取得结果**。传输记录包括 `transferId`、方向、`serverId`、文件/目录数量、字节数、状态和失败原因；不记录正文。具体类型名由实现确定，跨 Rust、IPC 和 UI 使用同一份契约与 fixture。

- **入口：**本机文件选择器、系统文件管理器拖入、远端文件列表的下载/拖放、双栏本机与远端文件视图。选择目标后明确显示本机目标目录名称、远端服务器和远端目录；完整本机绝对路径只留在 Rust 宿主，不进入 WebView 或 IPC。多个文件及目录递归传输均纳入目标；首版不跟随或复制符号链接，不传特殊设备文件。遇到这类条目要逐项报错并把批次标为“部分完成”，不能把剩余文件的成功冒充整个目录成功。
- **字节路径：**文件内容由 Rust 宿主在本机文件与 SFTP 之间分块流动。WebView 和 sidecar 只传句柄、元数据及进度事件，不承载整文件字节或绝对路径授权。预览调用保持独立的大小上限；大文件和二进制文件仍能完整传输。
- **上传：**先写远端独占临时文件，核对写入字节数和读回摘要后发布到目标路径；目标已存在时先让用户选跳过、改名或覆盖。覆盖需显示目标信息并独立确认，确认后再次检查目标。SFTP 没有通用 CAS：服务端不支持安全的无覆盖发布时应拒绝该模式；覆盖发布的最后一次检查与改名之间仍有竞争窗口，界面和记录必须如实说明，不能宣称事务性覆盖。失败/取消清理本次临时文件，并明确报告是否留下待处理产物。
- **下载：**先写本机同目录临时文件，核对完整字节数及来源摘要后发布；若远端不能提供独立摘要，则通过第二次读取复核或将结果标为“未独立验证”，不能虚报哈希一致。同名冲突同样处理。下载中断不得把不完整文件呈现为已完成。上传、下载都支持可见的逐文件与总体进度、取消、传输后核验、失败后的重试或重新开始；若尚未实现断点续传，界面不得显示“继续传输”。
- **生命周期：**每个传输任务有确定的排队、运行、待用户处理冲突、完成、失败、取消和中断状态；应用异常退出后重开要将未完成任务标为中断并处理遗留 staging，不得恢复成“已完成”。多个任务限制并发与本机/远端资源占用，进度事件丢失后可从宿主查询最新快照。
- **拖放：**Windows、macOS、Linux 的真实桌面应用均须实测系统文件管理器拖入上传。本机/远端双栏之间拖放可双向传输；远端拖出到系统文件管理器也属于目标能力，可用各平台原生适配器完成落盘与临时文件交接，通用传输逻辑仍在 Rust。系统限制导致某种拖出方式不可用时，交付记录要单列平台缺口，保留清晰的“下载到…”入口，不能把入口替代当作拖出通过。
- **预览：**本机和远端均可预览受限的 UTF-8 文本与常见图片；本机预览提供“上传到当前远端目录”，远端预览提供“下载到…”动作，不要求先关闭预览重新选文件。对 PDF/其他二进制至少显示类型、大小和“下载/用本机程序打开”动作，不把有损解码文本当成原文件。预览应显示截断、加载失败和无法识别类型，并且预览失败不阻断传输。若要让 PDF 内嵌可视预览，需另立可验证的类型与平台验收项。
- **安全：**本机来源来自原生选择/拖放授予的短期句柄，远端目的地由当前已连接的 `serverId` 与规范化路径绑定。拒绝路径穿越、NUL/控制字符、越界链接、目录递归环和特殊设备文件。下载内容不能通过远端文件名决定任意本机路径。手动传输只使用当前用户的连接，不能被模型伪装成 UI 点击。

## 施工顺序与交付物

每一步完成后提交可独立复核的代码、测试和文档差异；不要先重做外观再补底层。跨层字段从 `packages/shared` 契约开始，Rust 镜像、IPC fixture、Agent 和 UI 同步修改。既有用户数据需要迁移时补迁移与旧库启动回归。

| 阶段 | 实施细节 | 阶段完成条件 |
| --- | --- | --- |
| 0. 基线 | 运行 `pnpm check`，记录提交和现有失败；核对真实 Provider、SSH 测试机与三平台 GUI 环境，保持安装包历史证据不变 | 基线日志和环境清单可复现，已知缺口与本页一致 |
| 1. Agent 命令链 | 先审查现有共享 schema、`server.exec`、任务命令票据、宿主一次性批准、SSH executor 和错误持久化；只补契约缺口。核对命令目标只能由宿主任务解析，明确区分拒绝、超时、取消、执行结果未知、非零退出；启动恢复须禁止未知结果自动重放并撤销旧任务命令票据 | 自动回归覆盖未授权、过期、超预算、跨目标、审批重放、拒绝/停止、超时、非零退出、断连结果未知及进程重开；真实 SSH 验收确认远端事实与审计一致 |
| 2. 目标驱动编排 | 从用户自然语言目标创建任务；Agent 读取服务器与工具/MCP目录，自动产生可见计划并选择工具，执行后调用独立验证步骤。只在信息缺失、能力未配置、审批边界或无法核实现场时打断用户。工作区显示每步的工具、目标、开始/结束时间、输入/输出摘要和状态 | 用真实 Provider/MCP 和可重置开发/预发布主机完成依赖步骤任务；批准后的既定任务范围无需逐条确认普通高风险命令；Agent 依据远端读回证据报告结果 |
| 3. 观测工作区 | 复核现有刷新/过期/来源状态、服务/日志/文件导航、服务器近期动态和持久任务时间线；补齐订阅恢复、serverId 隔离、审批等待、验证失败和结果未知后的操作入口。人工终端仍是独立显式操作 | 不进入聊天视图即可判断所选服务器状态和数据新鲜度；从异常卡片进入实际活动/步骤记录，重启后仍能查看历史过程 |
| 4. 传输模块 | 复核 `crates/filesystem`、宿主生命周期、SQLite 快照及文件 IPC；保持字节只在 Rust 本机/SFTP 分块流动。新目标发布使用已协商的 `hardlink@openssh.com:1` 同目录 no-replace 发布；扩展缺失必须失败关闭，不能退化为普通 SFTP v3 `RENAME`。协议参考 [OpenSSH hardlink 扩展 v1](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL#L2285-L2306) 与 [POSIX `link()`](https://pubs.opengroup.org/onlinepubs/009695399/functions/link.html)。覆盖保持关闭 | 回环测试通过并有真实 OpenSSH 核验；失败、取消、目标碰撞、进程退出、staging 清理和部分完成状态均能准确恢复/展示；覆盖未实现前不提供覆盖上传 |
| 5. 文件界面 | 复核当前本机待传队列、系统文件拖入、队列↔当前远端目录拖放、预览页上传/下载动作和原生远端文件拖出；检查无效/过期句柄、路径越权、冲突对话框和逐文件进度。预览上限不限制完整传输 | Windows、macOS、Linux 安装版分别从系统文件管理器拖入上传、远端拖出、双栏传输、预览中发起传输，并完成中止/重开验证；无假预览或假成功 |
| 6. 整体验收与发布 | 跑自动门禁、真实 Provider/MCP/OpenSSH、可重置主机和安装后 GUI 路径；执行下面的正反例，留脱敏证据；更新 `docs/release.md` 的逐项状态 | 所有必需条件有对应提交、测试环境、产物哈希和操作证据；未通过项继续标未完成 |

可并行开发观测界面和传输模块，但阶段 1 的目标/权限接口与阶段 4 的传输接口各自必须先稳定再接 UI。增加 MCP 适配器时按实际出现的第二种实现抽取接缝；不要为每个按钮建一层只转发参数的模块。

## 验收条件（发布必须逐项通过）

每项记录 **提交 SHA、应用/安装包版本及哈希、平台、Provider/MCP/SSH 实现与版本、测试服务器环境、步骤、预期、实际结果、脱敏日志或录屏位置**。本地单元测试、回环协议测试、真实远端测试和安装后 GUI 测试分开记，不能互相替代。

| ID | 场景与可观察通过条件 |
| --- | --- |
| A1 目标执行 | 干净安装后添加并核验测试服务器、配置 Provider，启用所需内建/MCP 工具。用户只提交目标和一次明确的任务委托；Agent 自动读取现场、选工具、创建可见计划、执行至少两个有依赖的步骤并独立验证。UI 与持久活动记录显示目标、真实服务器、工具来源、输入/结果摘要、命令退出码、步骤时间和最终状态。 |
| A2 工具生态 | 同一真实任务至少调用一个内建工具和一个已配置 MCP 工具；断开或禁用 MCP 后目录与运行结果明确变化，不发生隐式回退或伪成功。外部工具的目标和副作用无法核实时必须等待批准。 |
| A3 命令权限 | 真实测试机上验证允许的只读命令、获批的配置命令、拒绝批准、跨 `serverId`、环境变化、主机指纹变化、超时、停止、非零退出与断线未知结果；每种情况与远端状态、UI 状态、审计记录一致。 |
| A4 自主程度 | 在开发/预发布测试机，用户一次给出目标并授权该任务的命令范围后，Agent 可连续执行至少两条此前未知的高风险命令及范围内的结构化工具调用，最后自行验证；不再逐命令要求点击。票据过期、预算耗尽、跨服务器、关键危险操作、生产或未知环境均停止并按具体输入重新询问。 |
| O1 状态 | 已连接、断连、采集中、过期、部分采集失败与恢复在界面可区分；CPU/内存/磁盘/服务或容器数据对应正确服务器、有来源和时间；旧数据不写成“实时”。 |
| O2 接管 | 运维人员能从异常状态定位日志、服务、文件和任务；批准等待、执行中、验证失败、结果未知、完成各有实际步骤和下一步。应用在运行中或等待批准时退出并重开后，活动、未完成步骤、目标/时间线可查；结果未知必须提示先做只读核查，旧命令授权已撤销且不得自动重试。 |
| F1 上传 | 三平台安装版分别从系统文件管理器拖入单个/多个文件及目录上传，并用选择器重复；空文件、中文/空格文件名、二进制及至少 256 MiB 文件逐字节或 SHA-256 一致，进度到完成后远端可读。新目标上传须核实并记录协商的 `hardlink@openssh.com:1`；若服务端不支持，预期为明确失败且清理 staging，清理失败时须显示待处理残留。目标在预检查后出现时不得覆盖；若最终文件已发布并校验但 staging 清理失败，结果须显示部分完成、已发布文件和待清理 staging。真实 OpenSSH 主机和三平台安装版分别验收；本地回环测试不能代替这两项。覆盖仍未实现，不能据此判定覆盖场景通过。 |
| F2 下载 | 三平台安装版分别从远端列表下载到指定本机目录、从远端列表拖至本机队列/双栏位置，并拖出到系统文件管理器；至少 256 MiB 文件与独立来源摘要一致，无法独立核验时明确标注。本机已存在同名文件时按跳过、改名、确认覆盖逐一验证。远端单文件原生拖出使用已准备的私有暂存内容和一次性票据，且不能暴露绝对路径给 WebView。 |
| F3 失败与隔离 | 上传和下载分别在断网、取消、权限不足、空间不足、源文件变化、目标冲突/变化、符号链接与目录环时测试；无假成功、无不完整目标冒充完成、无跨目标路径写入。能指出并清理本次 staging 文件。 |
| F4 预览 | 本机和远端文本/图片可预览，截断与加载错误可见；本机预览可直接上传当前远端目录，远端预览可直接下载到用户选定路径。二进制或不支持类型显示元数据和完整传输入口。预览的 1 MiB 限制不限制完整传输。 |
| R1 安装后交付 | Windows MSI/NSIS、macOS、Linux 的干净用户环境分别安装、重启、运行 A/O/F 路径；无系统 Node 的测试环境验证随包 Agent；退出/卸载后的进程和用户数据策略按[发布文档](./release.md)检查。 |

**不通过的判据：**只展示模型写出的命令而未实际调用；把用户手动终端输入算作 Agent 执行；用内存 fixture 代替真实 SSH/Provider/MCP；把截断预览算作下载；仅有按钮或浏览器预览而没有系统拖放；失败、取消或结果未知标成成功；只在开发 checkout 跑通而未在安装版跑通。

## 给接手 agent 的交付格式

1. 先读本页、[产品定义](./product.md)、[安全与数据边界](./security.md)和[交付与发布](./release.md)，再按“基线 → 契约 → 宿主 → Agent/UI → 真实验收”的顺序施工。
2. 每阶段在变更说明中列出改过的接口、用户可见行为、测试命令及实际结果、剩余风险。若验收条件需要调整，写明原因和新的可观察标准，不能直接删除失败用例。
3. 用 A/O/F/R 编号回填发布证据。全部通过前，README 和 release 只能写“目标”或“未验收”，不能把此设计文档当成已交付证明。

可直接发送给下一位 agent 的起始任务：

> 以 `docs/architecture-and-build-plan.md` 为目标和验收基准继续 Yukinal 施工。先复核本工作树的跨层实现并运行基线，尤其检查 `server.exec` 授权/结果未知恢复、任务实际步骤时间线、Overview 近期动态、本机队列与远端文件拖放、预览上传/下载和传输生命周期；补齐缺口，不重做已有模块。按阶段 0–6 完成真实 Provider/MCP/SSH 的目标驱动运维、多服务器状态接管、Windows/macOS/Linux 文件传输与安装版验收。新目标上传已实现协商 `hardlink@openssh.com:1` no-replace 发布；用真实 OpenSSH 核验扩展协商、竞争目标不覆盖和 staging 清理；扩展缺失时保持失败关闭。覆盖上传保持关闭。最后按 A1–A4、O1–O2、F1–F4、R1 提供证据，未通过项明确标未完成，不以自动测试、安装包 smoke 或模型描述替代实际目标状态核验。
