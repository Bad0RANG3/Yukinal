# Windows 桌面窗口方向

本阶段将 Yukinal 定义为 Windows 桌面工作区。React/WebView 是窗口内的界面实现，浏览器开发页只用于预览内容，不代表桌面窗体验收。

## 双圆角是窗体结构

外层由 Windows 顶层窗口承载，包含原生标题／状态带；内层是实际嵌入的 WebView 子窗口。外圆角由 DWM 决定，内圆角由 Win32 子窗口区域裁切。不要在网页中再画一层外框、标题栏或最小化／最大化／关闭按钮。

当前初始比例为：顶部状态带 40 DIP，内容两侧和底部留边 8 DIP，内容圆角半径 14 DIP。数值随窗口 DPI 缩放，是产品初始选择，不是 HIG 的规定值。Windows 11 的 DWM 决定外圆角；系统不支持时仍保留原生窗口管理。最大化时外框遵循系统形态，主体保留内层留边。

移动、缩放、系统菜单、标题栏按钮和 Snap 保留 Windows 行为。内容区不能通过遮盖原生按钮或接管整条顶部命中区域来换取视觉一致。

## 窗体和主体是一套工作区

外层不是独立装饰：它要成为工作区的常驻状态与功能区域，与主体共享导航、选中服务器和任务状态。当前落实如下：

| 信息 | 唯一来源 | 原生呈现 |
| --- | --- | --- |
| 当前服务器／项目／排查／动态／设置 | 现有 workspace store | 顶部上下文及系统窗口标题 |
| 选中服务器名称与连接状态 | 现有服务器查询缓存 | 服务器页面的上下文及状态 |
| Agent 是否工作中 | 现有 workspace store | 顶部运行状态 |

`WindowFrame` 观察现有状态，不新建轮询、服务器选择或 Agent 状态机。`windowShell.updateContext` 经共享 schema 和 C++ 独立校验后更新原生呈现；字段有明确类型、长度和枚举上限。名称不能含控制字符或无效 Unicode。通道不接受密钥、提示词、命令或审批授权。

之后可以将连接、任务控制等部分功能放入外层，但必须先定义明确动作，并接回现有应用服务和权限流程。不能另外建立一套服务器操作、Agent 循环或批准机制。窗口层不直接操作数据库、凭据或远端命令。

## 视觉衔接

顶部、导航和主体使用连续的石墨灰层次；系统 UI 字体承担界面文字，等宽字体保留给终端和代码。窗口内不叠加多层圆角外框；分栏通过表面层次、间距和细分隔线组织。引导页采用连续设置段落，减少套卡。

窗体与主体后续必须一起定义主题、激活／非激活、焦点、悬停和密度规则。当前原生颜色与 React token 尚未共用运行时主题通道；本次确定深色基线，主题同步作为后续实现。

## 本次边界与验收

本次交付原生双圆角结构、连续内容表面、状态互联及契约校验。窗体业务按钮、可编辑标题栏、完整主题同步、安装包和其他平台不属于本次实现。

自动验证覆盖上下文枚举、空值、长度、Unicode、未知字段、旧宿主兼容及错误传播；它不能替代原生窗口操作。原生验收需要逐项检查：拖动、边角缩放、按钮悬停、Snap、最小化恢复、最大化恢复、激活切换，以及跨不同 DPI 显示器移动。未执行的项目须在 PR 中明确保留，不能以浏览器截图或编译通过代替。

实现入口及宿主边界见 [C++ 桌面宿主](./native-desktop-host.md)。
