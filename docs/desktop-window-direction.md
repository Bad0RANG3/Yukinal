# Windows 桌面窗口方向

本阶段将 Yukinal 定义为 Windows 桌面工作区。React/WebView 是窗口内的界面实现，浏览器开发页只用于预览内容，不代表桌面窗体验收。

## 双圆角是窗体结构

外层由 Windows 顶层窗口承载，包含原生标题／状态带；内层是实际嵌入的 WebView 子窗口。外圆角由 DWM 决定，内圆角由 Win32 子窗口区域裁切。不要在网页中再画一层外框、标题栏或最小化／最大化／关闭按钮。

标题栏统一为 40 个逻辑像素（100% 缩放时为 40 px），原生窗口按钮在这一高度内垂直居中。左侧功能区固定为 240 DIP，主体占据剩余宽度；不使用 3:7 分配。主体右侧和底部留边 8 DIP，内圆角半径 14 DIP，最小窗口为 1100 × 680。数值随窗口 DPI 缩放，是产品初始选择，不是 HIG 的规定值。Windows 11 的 DWM 决定外圆角；系统不支持时仍保留原生窗口管理。最大化时外框遵循系统形态。

标题与窗口按钮由 Win32 绘制，最小化、最大化／还原、关闭通过系统窗口命令执行。最大化按钮保留 `HTMAXBUTTON` 命中，供 Windows 处理 Snap 悬停；拖动、边角缩放和系统菜单交回原生窗口过程。WebView 不绘制这些按钮。

## 窗体和主体是一套工作区

外层不是独立装饰：它要成为工作区的常驻状态与功能区域，与主体共享导航、选中服务器和任务状态。当前落实如下：

| 信息 | 唯一来源 | 原生呈现 |
| --- | --- | --- |
| 当前服务器／项目／排查／动态／设置 | 现有 workspace store | 顶部上下文及系统窗口标题 |
| 选中服务器名称与连接状态 | 现有服务器查询缓存 | 服务器页面的上下文及状态 |
| Agent 是否工作中 | 现有 workspace store | 顶部运行状态 |
| 工作区导航 | 现有 workspace store | 外框左侧导航按钮 |
| 服务器搜索和选择 | 同一服务器查询缓存 | 外框搜索框与原生列表 |
| 添加、刷新、编辑、连接／断开、删除 | 现有 React 弹窗和 server action 服务 | 外框按钮及列表右键菜单 |

`WindowFrame` 观察现有状态，不新建轮询、服务器选择或 Agent 状态机。`windowShell.updateContext` 经共享 schema 和 C++ 独立校验后更新原生呈现；字段有明确类型、长度和枚举上限。名称不能含控制字符或无效 Unicode。通道不接受密钥、提示词、命令或审批授权。

`NativeSidebar` 观察同一查询缓存，不增加轮询。原生控件只发送限定动作和服务器 ID；React 校验动作、重新解析当前服务器并调用既有服务。删除仍需现有确认，弹窗与进行中的操作阻塞外框动作，连接／断开仍检查当前状态。窗口层不直接操作数据库、凭据或远端命令。侧栏能力是可选接口，旧宿主和浏览器保留 React 导航。

## 视觉衔接

顶部与左侧外框统一使用更深的 `#141518`，主体基底为 `#202124`；外框用颜色和职责形成连续区域。系统 UI 字体承担界面文字，等宽字体保留给终端和代码。窗口内不叠加多层圆角外框；分栏通过表面层次、间距和细分隔线组织。引导页采用连续设置段落，减少套卡。

窗体与主体后续必须一起定义主题、激活／非激活、焦点、悬停和密度规则。当前原生颜色与 React token 尚未共用运行时主题通道；本次确定深色基线，主题同步作为后续实现。

## 本次边界与验收

本次交付原生双圆角结构、固定窄侧栏、40 px 标题栏、状态与导航互联及契约校验。任务控制、可编辑标题栏、完整主题同步、安装包和其他平台不属于本次实现。现有 C++ 宿主尚未接通的 Agent／SSH 命令不由窗口层补造。

自动验证覆盖上下文与侧栏契约、Unicode、重复／失效 ID、未知字段、订阅清理、旧宿主兼容、删除确认与忙碌状态，以及多 DPI 布局计算；它不能替代原生窗口操作。原生验收需要逐项检查：拖动、边角缩放、按钮悬停、Snap、最小化恢复、最大化恢复、激活切换，以及跨不同 DPI 显示器移动。未执行的项目须在 PR 中明确保留，不能以浏览器截图或编译通过代替。

实现入口及宿主边界见 [C++ 桌面宿主](./native-desktop-host.md)。
