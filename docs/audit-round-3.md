# 第三轮审计：本地 GUI、数据流与响应式布局

日期：2026-09-21。审计对象是 `http://127.0.0.1:1420/?fixture=1` 的 Vite 本地预览；所有服务器、运行记录、日志、任务、Provider 与主机指纹都是静态虚构数据，不含真实主机、账号、密钥或远程网络请求。

## Fixture 设计

`apps/desktop/src/lib/preview-fixtures.ts` 只在 Vite 开发环境且 URL 明确带 `fixture=1` 时启用。`callDesktopParsed()` 仍对 fixture 返回值执行同一份 shared Zod response schema；非原生浏览器的事件订阅返回 no-op，外部链接仍只允许原生桌面壳打开。

数据包含四种服务器状态、生产/预发布/开发环境、长服务器名、82% 内存和 85% 磁盘告警、容器、项目、任务、活动追踪和工具调用。终端 fixture 只返回一个静默本地 session 用来检验 xterm 版面，绝不伪造 SSH 输出或远程会话。

## 确认问题与修复

| 编号 | 发现 | 修复 | 复核 |
| --- | --- | --- | --- |
| GUI-01（P1） | 浏览器预览仍尝试订阅 Tauri 原生事件，产生未处理错误 | `listenDesktop()` 先确认原生壳；fixture 下为无操作取消器 | reload 后控制台无错误 |
| GUI-02（P1） | 约 1,024 px 时默认 Agent 覆盖工作区 | 初始响应式状态在小于等于 1,150 px 时收起 Agent | 概览完整可读，且 Agent 按钮可重新打开面板 |
| GUI-03（P2） | 480 px 下“刷新”按钮可按中文字形断成竖排 | 主/次按钮增加 `white-space: nowrap` | 项目页的刷新控件保持单行 |
| GUI-04（P2） | fixture 缺少终端响应时会显示 schema 错误，无法区分 UI 与传输失败 | 增加严格 schema 通过的静默 fixture session | 终端容器加载，无 alert |

## 仍受环境限制

- 真实 SSH、SSH 认证挑战、PTY 数据、文件写入、Provider、MCP 和 OAuth 流程没有在本轮 GUI 中执行。
- 截图只能发现当前 fixture 覆盖的布局问题；真实长日志、系统字体、DPI 缩放、输入法和安装后的 WebView 仍需在目标机器上验收。
- 本轮没有把虚构 UI 成功状态当作远程连接成功或安全验证成功。
