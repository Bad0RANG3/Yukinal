# AI、上下文与 Loop-agent 验收

验收分为确定性回归、原生界面、真实模型、目标执行四道门。每道门单独记录结果、时间、运行版本和证据；上一道通过不代表下一道通过。系统提示词正文、API key 和登录凭据不得写入验收记录。

## 1. 确定性回归

从仓库根目录执行 `pnpm check:ai`。可通过 `YUKINAL_AGENT_PYTHON` 指定已安装 Agent 依赖的 Python。缺文件、依赖缺失或测试失败必须返回非零；不能用跳过代替通过。

此入口依次构建共享契约、检查桌面类型、运行桌面测试，再执行 AI 运行时、宿主工具、策略、Provider 存储、推理路由和持久计划结算的 Python 测试集。使用临时数据、脚本模型及本地 HTTP/SSE 夹具，不证明真实 DeepSeek 可用。

| 验收项 | 通过条件 |
| --- | --- |
| 流式回复 | 模型完成前收到首个正文增量；结束正文一致且终态只发一次；工具、审批、取消和失败不遗留尾块或混入旧会话 |
| 工具循环 | 模型请求经注册表执行，结果回到下一轮；有步骤、调用数及输入上限 |
| 批准与恢复 | 批准只绑定原调用；拒绝、过期、未知执行结果不会盲目重试 |
| 上下文 | 同一会话续接；服务器/会话/参与者隔离；压缩保留成对工具记录；重置不删除原记录 |
| 失败收束 | 上下文准备失败和排队取消均进入终态；单次终态通知尝试；带任务标识；清除活动运行 |
| 模型路由 | 走真实子任务启动链验证继承、显式绑定和供应商默认模型；更换模型不误带父推理强度；失效绑定不回退；上下文、取消与配置快照隔离 |
| 私有推理 | SDK 流中的 reasoning_content 经工具轮、持久上下文和批准 checkpoint 恢复后仅回传模型；公开事件和终态不含私有字段或内容；推理强度四档参数及不支持组合明确校验 |
| 提示词边界 | 模型仍收到当前内部指令；普通转录与新运行元数据不包含其正文 |
| 设置请求 | 未打开的页不加载；隐藏页不产生自身请求；切换页保留编辑草稿；对话健康检查继续 |
| 持久计划结算 | 成功工具结果推进并持久化当前计划步骤；同一 call ID 重放不重复推进；最终步骤完成计划；结算失败后不重跑已成功的工具。Python 与 C++ 宿主处理器分别由本地回归覆盖；这不代替安装版 UI 的实时验收 |

本轮大型任务与界面过程结果见[连续工作流验收记录](ai-large-task-acceptance-20261018.md)。

## 2. 原生界面

使用当前构建的 Yukinal 窗口逐项操作，记录版本与实际截图/可访问性观察。

1. 运维 Agent 的模型分区明确显示单 Agent 与 subagent 共用当前对话模型；不出现已移除的 MoE 路由、彩色角色队列或系统提示词编辑器。
2. 对话设置清楚呈现当前运行模式和批准方式；运维 Agent 模型页明确显示其与 subagent 共用当前对话模型。已移除的自动团队分工、手动角色/能力选择和旧路由恢复控件不得重新出现。
3. 当前 DeepSeek 连接和模型以实际配置显示；继承当前对话与连接失效分别显示。更改只对后续运行生效。
4. 打开/切换/返回设置分区，编辑草稿仍在；诊断日志收起时不请求日志。
5. 最大化与还原窗口检查：文字换行、模型选择、保存反馈和滚动区域可操作。
6. 回复以紧凑正文展示，思考与工具过程可折叠；手动上滚不被新增内容拉回。
7. 结果、步骤、指标趋势、进度和详情按回复提供的数据展示；流式未完成与无效结构保留可读内容，复制得到正文与数值，历史回放不重复入场动画。

## 3. 真实模型

在专用测试会话中使用已配置 DeepSeek。界面验收通过 Yukinal UI；不操作界面时可通过产品 PythonSidecar RPC、ProviderStore、ModelFactory 和现有凭据模块组成受限验收入口，不能用直接 SDK 请求替代产品调用。两条路径分别记录，API 结果不代表已验证界面显示或原生 stdio 传输。

1. 多轮上下文：第一轮保存随机验收标记和约束，第二轮在不重复标记的情况下准确回忆并遵守约束；记录输入和回复。
2. 工具循环：使用产品注册的只读工具完成有界读取；核对实际运行中的调用、结果与最终答复。不以模型自述替代工具证据；需要纯计算的附加测试只用本地 fixture，不执行远程动作。
3. 取消：运行中停止后应终止，不因迟到事件回到运行中；重新发送能得到独立新运行。
4. 流式：通过真实模型确认首段在回复完成前显示；核对停止、工具和审批前的正文完整性，不把本地桩计时当作线上延迟。
5. 模型不可用/超时：有明确失败状态，输入或上下文仍可恢复。使用测试 Provider 完成故障注入，不能改真实密钥制造错误。

真实测试需设轮数、请求总数、输出和超时上限，并记录实际 API 请求而非仅模型对象创建数。同一 SDK HTTP 客户端只安装一次观测器，避免共享连接被重复计数。模型不一定每次都返回私有推理；有返回时再核对回传和公开隔离，不能把空字段判为丢失。

真实模型的自述不作为工具执行证据。缺少任务卡、调用标识、工具返回或可核对结果时，应记“待验证”。

## 4. 目标执行与最终通过条件

目标命令必须由 Yukinal 发起，按绑定的目标、计划、工具参数和批准执行。每步需要可核对的工具结果，才能结算计划步骤；只有 Agent 的 completed 事件不能证明服务器命令成功。
