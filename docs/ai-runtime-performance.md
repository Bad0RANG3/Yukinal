# AI 运行与对话体验

本轮改动解决目标任务过早结束、工具结果被二次截断、连续操作占满对话，以及模型回复过度解释的问题。

## 目标执行

普通 goal 运行取消默认工具调用次数和模型轮数配额；明确传入的任务预算继续生效。普通 goal 默认 10 分钟，明确要求持续执行的多阶段目标默认 30 分钟；运行仍受取消、总时长、输入和输出预算约束。readonly / plan 继续保留有界探测预算。

当前用户要求长任务、持续执行，或完整实现、部署和测试等多阶段工作时，未绑定调查任务的 goal 运行启用独立完成检查。阶段性正文会回到同一执行循环，每累计 20 次调用也会核对剩余验收要求。检查只引用实际成功的工具记录；未完成、无进展或真实阻塞不会被报告为完成。检查不是持久调度，关闭进程后不会继续工作。

本地参数校验失败可把注册 schema 和脱敏错误反馈给模型修正，未通过的调用不进入执行器。重复且结果不变的操作会被拦截。超时代表结果未知：单调用或纯读批次可以回到目标循环检查实际状态，混合或写批次停止，避免未知结果后继续依赖变更。不会自动重放超时操作。

模型产生的 `server.exec` 命令在审核前规范化为幂等的 `set -e` 前缀。审批、调用事件和实际执行使用同一份命令，旧命令的批准不能授权规范化后的输入。预期失败的探测应使用显式条件分支。

权限与宿主计划边界沿用主分支：没有对应计划绑定的宿主变更工具不会因为启用团队或长任务而获得执行权限。本 PR 不加入另一轮开发中的权限模式和自动计划功能。

## 推理、并行与上下文

仅对适配器确认支持、使用官方 HTTPS 端点的 DeepSeek 模型自动选择推理参数；手动选择优先，未确认的端点保留 Provider 参数。简短公开回复与模型输出预算分别处理，实际运行不复用连接探针的 256 token 限额。缓存 token、推理 token、请求耗时和首段正文耗时只记录实际回报或本地计时，不估算缺失用量。

连续、明确标记为 `parallel_safe` 的独立只读工具最多并行 3 个；写入、审批、协调调用和未标记工具形成顺序边界。结果按模型原始调用顺序归并。保存团队配置不会把普通问题自动变为团队任务，明确委派或适合独立职责的大任务仍可分派后台团队。

会话历史达到可用文本预算的 80% 时，投影收缩至约 60%，保留完整最近轮次、原始目标锚点、相关历史摘录和较新的修正。原记录保留在本地；摘录被标记为非可信历史，不能提供新授权。大型工具结果向模型提供带有截断标记的首尾摘录，需要缺失内容时应缩小查询范围。预算单位是序列化文本字节，不冒充模型精确 token 窗口。

继续使用严格校验的 JSON。TOON 未替换工具、IPC 或存储格式；尚无足够的同任务收益与兼容性证据支持协议迁移。

## 持续值守与数据更新

只读目标登记值守计划后，由原生主窗口持有后台时钟，按计划到期异步启动运维巡检；不依赖团队面板是否打开。支持每 30 秒等自定义 AI 频率。启动、完成、失败、暂停、超时和重启中断均写入本地运行记录，下一轮不需要用户再次发送“继续”。同一任务的计划不会同时修改其取证计划；取消未确认时保留运行位置，避免重叠执行。

30 秒团队心跳只汇总 AI 用量，不负责数据更新。资源查询约每 5 秒、日志约每 3 秒、服务清单约每 10 秒更新；团队任务和值守状态各自刷新。未显示的远程日志和服务面板停止轮询，共享查询合并同一请求。轮询间隔不是采集延迟保证，实际刷新还取决于 SSH 和探针耗时。

巡检保留只读权限、任务范围和宿主计划检查，使用新会话采集当前证据，再参考上次结果或显式基线。没有成功读取当前数据、结果格式无效时显示证据不足。通知遵循静默、变化、每次或失败策略。应用退出期间不会执行；重启会将残留运行标记中断，再等待下一次到期。此实现不安装常驻守护服务，聊天中的单次团队派发本身仍不会自动登记值守计划。

巡检进度通过独立的 `investigation.schedule_activity` 通道发送运行绑定、阶段、工具名称和用量，不发送对话正文、工具参数或审批内容。值守面板显示运维操作边缘提示、中文结果和失败原因；团队入口及值守页签显示未读状态，打开对应计划后清除。后台巡检不修改主对话、草稿、焦点或导航。

用户主动询问值守时，路由模型可调用只读 `watch.status`，读取当前服务器最多 20 条已保存的计划和结果，并附采集时间。该工具不触发新巡检，不把历史结果当成实时探测。巡检内的 SSH 工具顺序执行，最近有效的对照结果不会被一次失败覆盖。本轮明确要求不用工具时，同时关闭工具执行、团队派发和持续目标续跑。

本地夹具覆盖 61 轮到期调度及变化通知，并覆盖实际原生到 Python 管道的异步启动和结果落库。夹具使用模拟模型和数据，不能证明真实模型识别入侵或靶机监控已经验收。

## 对话展示

回复默认一至三句，长任务阶段通常只给一句关键进展；最终先给结果，再用至多三条短项说明验收、未完成项和限制。用户要求研究、解释或完整文档时可充分展开。此规则是提示词约束，不会截掉用户所需的证据。

连续成功工具默认合并折叠，失败、等待审批和正在执行的操作保持可见。中间正文按真实后续活动标记为进展。命令摘要保持有效 JSON，标准输出、标准错误、截断标记和原始摘要可展开检查。文件正文仍不写入动态。对话轮次导航支持键盘操作，阅读历史时新增输出不抢走位置。

审批卡优先展示目的、目标和完整命令；全部参数、策略事实和审批标识仍可查看。按钮是否提供本次运行批准仍由宿主的 `sessionGrantable` 决定。

可视化通过本地严格 JSON 协议提供二维图表、坐标图、流程图和可旋转的三维信息场景，见 [绘图协议](./ai-visual-protocol.md)。三维场景是 SVG 投影，不是任意 CAD 或模型加载器。

## 验证边界

`pnpm check:ai` 覆盖流式输出、失败与取消、目标持续执行、参数修正、重复操作、只读并行、推理路由、上下文以及桌面呈现回归。模型与工具使用本地 fixture，不能替代真实 Provider 和原生窗口验收。

本轮此前在共享开发工作区通过产品界面执行过超过 50 个工具步骤的 Docker Web + PostgreSQL 部署，包含 22 项 HTTP 检查、重启数据保持及独立恢复数据核对。那次环境同时包含另一轮权限开发；本 PR 在最新主分支上单独跑回归，不能把共享工作区的整体验收直接视为本分支安装包验收。远端地址、凭据、截图和运行日志不进入仓库。
