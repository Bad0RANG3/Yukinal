# 大型任务、长对话与界面过程验收

执行时间：2026-10-18 至 2026-10-19。源分支：`codex/agent-streaming-ui-20261018`，在 `4ac13ac` 之上验证本次修改。未使用 Computer Use；未连接靶机，未执行远程攻防。

## 确定性连续流程

`pnpm check:ai` 已加入 `test_agent_long_workflow` 与 `test_agent_large_coordination`，使用真实产品 sidecar、上下文、协调和工具注册表，模型传输由严格本地检查器替代。它们检查模型实际收到的公开输入，不能从数据库补写模型答案。

| 场景 | 实际覆盖 |
| --- | --- |
| 160 轮累积对话 | 约 640 KB 原始记录、默认上下文字节预算、实际发生压缩；第 47 轮事实在第 140 轮首次回查，第 81 轮更正后第 160 轮采用新值 |
| 重开与隔离 | 第 80、120 轮重开；完整工具配对；新会话和实际子任务不继承主会话事实；重置保留原始历史但不召回旧上下文；五档实际 JSON 字节预算 |
| 连续依赖任务 | 20 个前景回合、49 个持久任务、9 条证据依赖、三版角色模型配置、失败后明确使用新 key 重试、跨会话拒绝与取消 |
| 容量与恢复 | 峰值 32 项接纳、3 个 worker；排队取消释放容量；崩溃快照重开后 32 项中断，无自动重放；新 key 才继续执行 |

初始 160 轮测试确实失败：早期事实从第 46 轮退出模型输入。修复为对公开摘要建立 FTS 索引，压缩时分别保留早期锚点、与当前问题匹配的旧摘要、近期摘要，并按原始时间顺序呈现。当前问题优先于长日志尾部的哈希；会话、服务器、epoch 和当前轮截止边界仍生效。索引更新使用原始轮次主键；旧库回填、删除与重开都有回归。输出仍受真实序列化字节预算限制，不能保证任意长原文中的每个细节永远在模型窗口内。

## 真实 DeepSeek 连续工作流

通过产品 PythonSidecar → ProviderStore → ModelFactory → DeepSeek 适配器，以及现有桌面凭据存储读取配置。只注册本地只读统计工具，不调用独立 SDK 入口，不向模型发送靶机或账户资料。

30 个连续阶段包括 22 批累计票据与诊断材料、约束更正、磁盘上下文重开、依赖排序、实际流式停止与新运行恢复、3 个真实角色任务和最后首次回问早期随机标记。此后进行 7 项定向复测，共 73 次模型请求，低于 80 次上限；所有已发请求的 HTTP 状态均为 200。真实私有推理回传仅记录存在性与计数，公开输出未包含其字段或正文。

原始 30 轮严格检查 23 项通过：6 项虽然工具回执数值正确，模型却输出了产品注入历史的“Earlier answer by …”前缀；修复为保持历史 assistant 正文原样，参与者归属作为单独参考元数据。6 项同历史定向复测与另 1 项压缩回查均通过。另 1 项协调汇总包含正确必需字段及额外角色信息，原检查器错误地要求对象完全相等；保留原失败记录并按必需字段校准，未为此新增模型请求。不能把这批结果写成“修复后完整 30 轮重新通过”。

测试夹具还出现过 SQLite 备份连接未显式关闭导致 Windows 临时文件清理失败。业务 7 项完成后才发生；夹具已改为显式关闭，进程退出后删除内部临时数据库，保留失败日志。该问题不归因产品。

应用层 MoE 验证的是角色路由、冻结模型绑定、独立任务和实际结果汇总；不证明供应商模型内部专家网络的行为，也不以私有推理文本评价思考质量。

## UI 与过程反馈

新增 40 项界面状态和转录身份检查，覆盖主要页面的加载、错误、空白、缓存错误及任务状态。关联定向 159 项通过；完整桌面测试包含这些新增检查。具体修复：

- 记忆读取失败与空状态互斥。
- 概览隐藏后停止活动查询和显示时钟。
- 日志错误分支保留与展开按钮对应的面板 ID。
- 动态条目创建时分配稳定身份，流式增量和工具更新保留；历史使用持久消息 ID，超过 500 条截头不按行号复用组件。
- 共享加载/错误面板补充状态和警告语义。
- 结果图表的 title 使用单一字符串，消除 React 19 警告。

本轮 UI 证据来自组件渲染、状态、查询选项与源规则检查；尚未验证原生窗口中的实际点击、焦点、滚动、动画、尺寸和截图视觉。远程服务、原生文件/终端操作与持续安防演练也不由本轮结果替代。
