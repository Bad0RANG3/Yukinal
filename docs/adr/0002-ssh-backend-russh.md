# ADR 0002 SSH 后端采用 russh

Status: Accepted
Date: 2026-09-09

## Context

Yukinal 需要一个跨平台的 SSH 后端，同时提供四类能力：建立带主机密钥校验的连接、执行一次性远程命令、申请交互式 PTY、以及通过 SFTP 读写文件。终端、概览采集、服务探测、日志读取、远程文件和 Agent 的文件工具全都建立在它之上，所以它的行为必须在三个平台上一致，也必须能在没有真实服务器的情况下被测试替换掉。

候选有三类：纯 Rust 实现（russh）、C 库绑定（libssh2）、以及调用系统 `ssh` 子进程。

## Decision

`crates/ssh` 使用 russh 作为默认实现，并通过 `SshBackend` trait 向上层暴露能力。russh 的类型不越过这个 crate 的边界：调用方只看到 `Session`、`SftpClient`、`CommandResult`、`PtySession` 这些自有类型。

工作区依赖固定在 `Cargo.toml`，并做了两处有意选择：

```toml
russh = { version = "0.63", default-features = false, features = ["ring", "flate2", "rsa"] }
russh-sftp = "2.0"
```

- 用 `ring` 而不是默认的 `aws-lc-rs`：`aws-lc-sys` 需要在每个平台上都有 C 工具链和 cmake，而 `ring` 为目标平台提供了预编译汇编，CI 的安装步骤因此不需要再加一套构建链。
- `rsa` 保留，因为相当一部分服务器仍在协商 `rsa-sha2-*` 主机密钥或用户密钥。

具体行为：

- **连接与认证整体受 15 秒硬超时约束**，避免界面卡在握手阶段；会话的空闲超时设为 60 秒；keepalive 间隔由 `SshConfig.keepalive_interval_secs` 决定（桌面端使用 30 秒，0 表示关闭）。keepalive 失败只记录日志，让后续操作走重连路径。
- **命令执行分两条路径。** 只读命令走 trait 方法，允许在 `Error::Transport` 上重连并重试一次；有副作用的命令必须走 `execute_once()`，它不重试——一次丢失的响应不能变成第二次重启。认证失败、主机密钥不匹配、参数错误都不重试。
- **远程命令输出有传输层上限**：单条命令的输出被限制在 4 MiB，防止远端进程把宿主的内存撑爆。更紧的语义上限由宿主命令层各自施加。
- **主机指纹按 `host:port` 保存在数据目录下的 `known_hosts`**（`crates/ssh/src/known_hosts.rs`）。连接前先查已钉指纹：命中就必须匹配，不匹配即返回 `Error::HostKeyVerification`；未命中时按策略决定行为——首次信任模式允许连接并在**认证成功之后**才落盘指纹（认证失败不留记录），严格模式直接拒绝并提示需要先显式信任。证书形式的主机密钥会被拒绝，而不是被当成普通密钥接受。
- **认证方式限于密码和未加密的 OpenSSH 私钥。** 私钥解析失败时会明确指出「带口令的私钥暂不支持」；`Authentication::Agent` 保留在枚举里，但调用即返回「ssh-agent 认证尚未实现」，不会静默降级到其他方式。
- **PTY 使用 `xterm-256color`**，并显式发送 `TTY_OP_END` 与关闭 `ONLCR` 的终端模式，让字节流原样到达 xterm.js，而不是被服务端二次改写换行。
- **SFTP 子系统按需惰性建立**，通过 `request_subsystem("sftp")` 打开并缓存在会话里；读取提供带字节上限的变体，写入提供整文件覆盖。

## Consequences

**收益**

- 不依赖系统 SSH 客户端，三平台的 PTY、SFTP 与命令行为更一致；CI 里可以直接对不可达地址断言错误映射（例如 `127.0.0.1:1` 必须映射为传输错误）。
- russh 的 0.x API 变动被限制在 `crates/ssh` 内，上层只依赖稳定 trait；替换实现不需要动 UI、Agent 或数据库。
- 原生化带来可测性：`SshBackend` 可以在测试里被替换，采集器与终端逻辑因此不需要真实服务器。

**成本**

- 需要自己维护主机密钥策略与 `known_hosts` 文件格式，不能复用用户已有的 `~/.ssh/known_hosts` 语义。
- 首次信任模式在开发场景很方便，但它意味着第一次连接本身就是信任决策。生产使用者必须在首次连接前独立核验指纹；严格匹配策略已经实现，但桌面端当前的连接路径尚未把它暴露给用户。
- 认证方式覆盖不全：没有 ssh-agent，也没有带口令的私钥，用户必须提供可被直接解析的私钥。
- 老旧服务器可能只支持我们未启用的算法；这类兼容性特判必须留在 `crates/ssh` 内部，不能渗到上层模块。

## Alternatives considered

- **libssh2 绑定。** 需要 C 工具链和线程模型适配，与 tokio 的异步路径结合更别扭，且跨平台的构建成本高于本项目的收益。否决。
- **调用系统 `ssh` 子进程。** 看起来最省事，但会继承用户 `~/.ssh/config`、agent 和 known_hosts 的行为，导致「同一份配置在不同机器上权限含义不同」；PTY 与 SFTP 也要靠额外的进程和协议去拼。否决。
- **同时支持多种后端并让用户选择。** 会让主机密钥、超时和取消语义出现多套实现，测试面翻倍，收益只是兼容性。等真的有需求再加，且必须走同一条 trait。
