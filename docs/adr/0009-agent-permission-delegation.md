# ADR 0009 Agent 权限采用显式运行级委托

Status: Accepted
Date: 2026-09-09

## Context

仅按目标环境策略执行时，生产写入和危险操作会等待用户，而开发环境的部分操作可自动执行。这个模型保护了环境边界，却无法同时满足两种常见工作方式：用户可能希望每次变更前确认，也可能希望 Agent 连续完成一项明确委托的任务。

放开自动执行也不能让模型的一段文本等同于授权。系统必须区分策略自动批准、用户逐项批准和用户委托 Agent 后的自主判断，才能在活动记录中说明责任来源。

## Decision

每次 Agent run 可接收 `permissionMode`：

| 模式 | 行为 |
| --- | --- |
| `ask` | 只读操作自动执行；写入、部署、重启和危险操作在执行前等待用户批准。 |
| `auto` | 用户明确委托 Agent 在开发或预发布目标上批准普通写入。高危、本机、未知或生产操作仍需逐项人工批准，策略拒绝仍然拒绝。 |

SDK 调用省略字段时继续遵循环境策略，以维持协议兼容。桌面 UI 默认使用 `ask`，并将用户选择随每次运行发送给 sidecar。

Permission Engine 仍是唯一生成 `ExecutionTicket` 的模块。`auto` 是用户在运行级作出的委托，不是模型在消息中声称拥有的权限。自动执行的审计来源分别记录为 `policy`、`agent` 或 `user`，Agent 自主批准不会伪装为用户批准。

`auto` 不会扩大到 dangerous tier。高危与 critical 操作、生产目标、未知目标和本机目标始终要求用户批准；任何 `deny` 都不能被模式覆盖。

## Consequences

- 用户可以在每次运行中选择逐项确认或委托 Agent 自动批准，并理解两者的差异。
- Agent 可以连续完成已委托的开发或预发布写入任务，但每项自动操作都会标为“Agent 自主批准”，并保留风险、目标和结果。
- ToolRegistry 增加 Agent 委托 ticket，仍校验工具名、解析目标、决策来源和风险，不接受模型伪造的 ticket。
- SQLite 的 `tool_executions.approved_by` 增加 `agent` 值，并通过版本迁移兼容已有数据库。
