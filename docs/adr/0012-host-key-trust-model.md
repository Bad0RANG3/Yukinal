# ADR 0012 主机指纹的信任模型：默认 TOFU，但必须能人工核验、钉住与遗忘

Status: Accepted
Date: 2026-09-12

## Context

[ADR 0002](0002-ssh-backend-russh.md) 把 SSH 关在 `crates/ssh` 的 `SshBackend` 之后。指纹这件事的能力其实已经在了：`KnownHostsStore` 能存能查（`<data_dir>/known_hosts`，自有 `v1:host:port:SHA256:…` 格式），`KnownHostsPolicy::RequireMatch` 能在 TCP 之前就拒绝未钉过的主机，`RusshBackend::trust_host()` 能钉住一个指纹，`Check::Mismatch` 能表达「钉住的与出示的不一致」。

问题在**没有出口**，而且缺的恰好是最需要的那一步：

- `trust_host()` 在整个仓库里**零调用方**；没有任何 Tauri 命令，没有任何界面元素（`fingerprint` / `hostKey` / `knownHosts` 在全部 TS/JS/JSON 里零匹配）。
- 桌面端唯一的生产配置把策略写死为 `TrustOnFirstUse`（`commands/terminal.rs`），因此 `RequireMatch` 只存在于测试里。
- 最糟的一条：**验证失败时用户看不到该看的指纹**。未钉住的主机在 `RequireMatch` 下报的是一个占位字符串（`"not pinned (first connect must be explicitly trusted)"`）；而「钉住的与出示的不一致」在 `check_server_key` 里返回 `false`，最终表现为一次通用握手失败——也就是说，一次可能的中间人攻击，或者一次完全正当的服务器密钥轮换，两者对用户的呈现是一样的，而且都没有给出新指纹。用户既无法判断，也无法接受。

## Decision

1. **默认仍是 TOFU。** 首次连接某台主机时自动信任并记录（与今天行为一致，不新增一步操作）。已钉住的主机按 pin 校验，不一致即拒绝（也与今天一致）。
2. **新增三个显式入口**（命令 + 界面动作，不是一个隐藏设置）：
   - **探针（probe）**：真的连一次，返回服务器**实际出示**的指纹，但**不写入任何东西**。用于「我手上有服务器运维给的指纹，要对照一下」。
   - **钉住（trust）**：把用户确认过的指纹写进 store。这是唯一会写 pin 的用户动作（首次连接的自动记录除外）。
   - **遗忘（forget）**：删除某个 `host:port` 的 pin，下一次连接回到 TOFU。
3. **验证失败必须同时给出两个指纹**：钉住的那个与出示的那个。`Error::HostKeyVerification` 的 `fingerprint` 字段不再承载「未钉住」这类占位说明，而是真实的出示指纹；未钉住且策略要求匹配时，改为一个语义明确的配置/策略错误。用户必须能一眼看出「哪一个是它，哪一个是它变了」。
4. **探针结果在被用户确认之前是不可信的**。界面文案必须写「服务器出示的指纹」，不能写「已验证」；探针也不得持久化任何状态（包括不能顺手把 pin 写进去）。
5. **不提供「不一致时仍然继续」**。没有「记住并继续」按钮，也没有自动接受：一次变更只能由用户先遗忘再重新探针确认。
6. **指纹格式与存储位置不变**：`SHA256:<base64 无填充>`（OpenSSH 的写法），存文件不存 SQLite。
7. **pin 按 `host:port` 关联，不按 server id 关联。** 这是有意的：同一台机器在两个服务器条目下必须共用同一条 pin，否则会出现两份互相矛盾的信任状态。

## Consequences

**收益**

- 指纹从「后端有能力但没出口」变成可核验、可钉住、可遗忘的操作；一次正当的密钥轮换不再把用户永久挡在门外（忘了再确认即可）。
- 失败变得可解释：两个指纹并列显示，用户能判断这是轮换还是攻击。
- 探针与信任分离，意味着「看一眼」不会改变任何状态——这对一个安全动作很重要：查看不应该有副作用。

**成本**

- 探针会真的发起一次连接并在服务器上留下一次（通常未认证的）连接与日志记录；它不是一个纯本地操作，文案必须说清楚。
- 首次连接仍然是 TOFU：不加一步确认意味着第一次连接仍然可能被中间人利用。这是接受下来的风险，不是遗忘。
- pin 与服务器条目不是一对一，用户可能对「我在 A 条目上忘了 pin，为什么 B 条目也放行了」感到意外；这条必须写在界面文案与文档里。
- 遗忘是危险动作：下一次连接会静默重新 TOFU。界面必须明确告知，而不是把「遗忘」做成一个无提示的行内按钮。
- 探针结果可能被误当成「已验证」（用户按了探针就当核验过）。只能靠文案缓解，无法靠机制消除。

## Alternatives considered

- **强制严格模式：首次连接必须人工核验。** 更安全，但把安全默认变成了使用障碍，真实结果是用户到处复制粘贴指纹而不是核验，或者干脆绕开这个应用。否决。
- **维持现状（只 TOFU，无入口）。** 一次合法的服务器密钥轮换会让用户永久无法连接，且无法看到新指纹；同时中间人攻击与轮换在界面上无法区分。这种「安全」是假的。否决。
- **把 pin 存进 SQLite 并按 server id 关联。** 同一 `host:port` 出现在两个条目时会得到两份互相矛盾的 pin，且与已有 `known_hosts` 文件形成两个真相来源。否决。
- **在不一致时提供「记住并继续」。** 那是一个把中间人攻击变成一次点击的按钮。否决。
