# 安全与数据边界

本页说明 Yukinal 当前实现和[目标架构](./architecture-and-build-plan.md)必须保持的信任边界。目标功能尚未全部实现；发现漏洞或需要私下报告时，请使用仓库根目录的[安全策略](../SECURITY.md)。

当前重写包含独立 C++ SSH 服务和 Python Agent。桌面为选中的 `serverId` 从 SQLite、系统凭据库和已确认的主机密钥 pin 生成单目标配置，再启动短时 C++ 服务进程。服务只监听回环地址并要求随机 bearer token；请求不能指定任意主机、凭据或原始命令。没有 Host CA 且使用直连或受支持 HTTP CONNECT 路由的主机指纹探测由 C++ 完成：探测目标没有 SSH 身份凭据和信任 pin，且只能执行握手探测；它只返回未验证指纹，不写本地状态。Host CA、HTTPS 代理、带 `NO_PROXY` 的代理或 C++ 不支持的 host-key 格式由 Rust 的证书感知探针处理。服务状态查询使用固定操作；桌面文件浏览和 Agent 文件读取、覆盖写入、备份创建、清理以及编辑/恢复使用 C++ SFTP 操作，适用于直连或无 bypass 规则的 HTTP CONNECT 代理、已确认主机密钥 pin、未配置 Host CA 且使用密码、私钥、OpenSSH 用户证书或 SSH Agent 身份的服务器。代理凭据通过 C++ 子进程环境变量传递，不写进目标 JSON；HTTPS 代理与配置了 `NO_PROXY` 的代理继续留在 Rust 路径。SSH Agent socket 仅在目标选择 Agent 认证时传给 C++ 子进程（Unix 使用 `SSH_AUTH_SOCK`，Windows 使用平台 Agent 接口）。支持的终端会话通过独立 C++ PTY 子进程连接，输入、尺寸变化和输出使用有界 JSON-lines 管道；该入口只由手动终端 UI 调用，不暴露给 Agent 工具。C++ 密码认证不适用时，键盘交互认证会回到 Rust 的用户确认流程。Host CA、HTTPS 代理、带 `NO_PROXY` 的代理、键盘交互认证及仅有 known_hosts 信任的终端仍使用 Rust。守卫式替换会复核目标的大小、mtime 和 SHA-256，在同目录独占创建暂存文件，保留并复核 mode/mtime/owner/group，再通过 OpenSSH POSIX 原子重命名发布；服务器不支持安全原子替换时会拒绝发布。受支持目标的手动文件传输使用 C++ SFTP 流式子进程：仅在直连或受支持 HTTP CONNECT 路由、已确认主机密钥 pin、无 Host CA 且身份受支持时启用，数据通过有界本机 JSON-lines 管道转发，不经过模型或 Agent sidecar；其他不兼容目标保留 Rust SFTP 回退。

## 谁能做决定

React 界面通过白名单 Tauri IPC 请求本地宿主。宿主持有原生 UI 桥接、SQLite、操作系统凭据库和本地子进程；C++ SSH 服务处理已迁移的结构化远端操作，Python Agent sidecar 负责模型会话和工具提议。模型输出、远端日志、文件内容和 MCP 描述都按不可信数据处理。

Agent 工具调用须经权限引擎和宿主复核：目标由本地解析，输入、风险、任务计划和授权票据要匹配。副作用工具绑定持久任务及计划步骤；危险操作不能仅靠提示词或模型声明获得授权。用户直接输入的终端命令是单独的人工操作入口。工作树中的 `server.exec` 是独立的受控 Agent 工具，必须走上述链路，不能复用终端输入通道或让 sidecar 直接握有 SSH 凭据；仍须按施工文档验收真实目标和失败边界。

## 用户批准意味着什么

- `readonly` 和 `plan` 运行模式阻止 Agent 产生副作用；`goal` 才可能进入执行路径。
- `ask` 与 `auto` 是批准方式，不改变运行模式或宿主硬边界。自动批准只适用于明确委托、符合环境和风险条件的操作。用户给出目标后可连续执行范围内的读取与普通结构化变更；扩展服务器、风险上限或操作类别要重新授权。
- 审批应显示具体服务器、操作、完整命令或足以核对的具体输入、风险和结果可能性。新的任意 shell 命令默认按高风险处理并逐条批准。目标架构允许用户对单个开发/预发布任务明确授权连续命令执行；票据绑定任务、服务器、环境、期限及调用/时长/输出预算，每次由宿主重验，不能扩到生产、未知环境或关键危险操作。命令模板只有在目标、程序和参数由宿主校验后才能降低对应调用风险；生产与关键操作仍按具体输入逐项询问。
- 拒绝或停止不会回滚已经完成的远端操作。结果未知时应进入待核对状态，不能显示“成功”。

## 凭据、数据和外部连接

SSH、Provider 与 MCP secret 交给操作系统凭据库；配置和数据库只保存必要的引用与任务元数据。跨机器复制数据库不能代替重新绑定系统凭据。主机指纹首次连接必须由用户通过可信渠道核验；指纹变化应拒绝连接并提示核查。

Python sidecar 在 `YUKINAL_DATA_DIR/agent-state/langgraph-checkpoints.sqlite` 保存 LangGraph 恢复状态，其中可能包含提示词、模型消息和工具结果。POSIX 上状态目录权限为 `0700`、数据库为 `0600`；Windows 使用每用户应用数据目录的 ACL。检查点启用严格 msgpack 反序列化，但 SQLite 文件本身未加密，因此本地备份和磁盘访问也应按敏感数据保护。该存储恢复同一运行的图状态，不等同于桌面任务和计划生命周期的完整恢复。

远端读取、日志、附件和 IPC 帧有大小或数量限制。提供给模型的内容必须受限并脱敏；审计记录应保留操作与结果的可追溯信息，避免写入凭据、完整远端正文和不必要的模型上下文。连接外部 Provider 或 MCP 服务器前，用户应知道相关数据会离开本机；MCP 自报的描述、schema 和风险注解不能单独成为授权依据。

本机↔远端的手动文件传输由用户在工作区发起。只有直连或无 bypass 规则的 HTTP CONNECT、已确认主机密钥 pin、未配置 Host CA 且使用受支持身份的目标才通过 Rust 宿主启动 C++ SFTP 流式子进程；数据以有界 JSON-lines 帧在本机进程间转发，不经过模型或 Agent sidecar。HTTPS 代理、配置了 `NO_PROXY` 的代理、Host CA 或其他不兼容目标保留 Rust SFTP 回退。原生选择/拖放授予的本机来源要绑定到短期传输句柄，远端目标绑定已核验的 `serverId` 和路径。上传/下载都要防路径穿越、符号链接越界、静默覆盖、不完整文件被当成完成；预览上限和传输上限分开。文件名、日志和预览内容仍按不可信输入显示。

## 明确的限制

- SFTP 文件变更没有跨系统原子 compare-and-swap；守卫式替换会在发布前复核内容，但最终复核与原子重命名之间仍可能竞态。
- 远端命令可能在停止或断线前已被服务器接受；退出码未知时需核对实际状态，不得自动重试非幂等操作。
- 模型结论不能替代人对生产变更的判断；服务器、MCP 或模型服务也可能在调用后才失败。
- 应用退出时不承诺后台巡检继续运行；停止 sidecar 不保证撤销外部系统已接受的操作。
- 安装包当前未签名，真实安装与真实端点的验收状态见[交付与发布](./release.md)。
