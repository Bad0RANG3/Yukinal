# 安全与数据边界

本页说明 Yukinal 当前实现和[目标架构](./architecture-and-build-plan.md)必须保持的信任边界。目标功能尚未全部实现；发现漏洞或需要私下报告时，请使用仓库根目录的[安全策略](../SECURITY.md)。

当前重写包含独立 C++ SSH/SFTP 服务和 Python Agent。桌面宿主依据选定的 `serverId`，从 SQLite、系统凭据库和已核验的信任配置生成单目标服务配置。C++ 服务只监听回环地址并要求随机 bearer token；请求不能替换目标、凭据或信任设置。Agent 的结构化操作由 Python caller 发送到 C++ 服务，原始命令只有在桌面授权链为单个目标启用一次性能力后才能执行，并受 C++ 参数、超时和输出上限约束。主机指纹探测由 C++ 完成：探测配置没有 SSH 身份凭据和信任 pin，只执行握手并返回未验证指纹，不写入信任状态。桌面文件浏览、Agent 文件读取/写入/备份/清理/编辑/恢复、终端和手动传输都由 C++ 承担 SSH/SFTP/PTY 会话。服务支持直连或受支持 bypass 规则的 HTTP/HTTPS CONNECT、SOCKS5/SOCKS5H，以及密码、私钥、OpenSSH 用户证书或 SSH Agent 身份；支持配置的 Host CA、KRL 和 pin/known_hosts 信任模式。代理凭据通过 C++ 子进程环境变量传递，不写入目标 JSON；HTTPS KRL 下载验证服务器证书，loopback HTTP KRL 必须绕过 SOCKS 代理，无法安全路由时拒绝连接而不跳过撤销检查。KRL `NO_PROXY` 端口匹配使用 KRL URL 的目标端口。SSH Agent socket 只在目标选择 Agent 认证时传给 C++ 子进程（Unix 使用 `SSH_AUTH_SOCK`，Windows 使用平台 Agent 接口）。交互式终端由独立 C++ PTY 子进程连接，通过有界 JSON-lines 管道向 UI 转发键盘交互挑战、尺寸和输出；终端入口只由手动 UI 调用，不暴露给 Agent 工具。C++ 不支持的认证、Host CA 算法、信任或代理配置明确失败，不回退到 Rust SSH/SFTP。守卫式文件替换会复核目标大小、mtime 和 SHA-256，在同目录独占创建暂存文件，保留并复核 mode/mtime/owner/group，再通过 OpenSSH POSIX 原子重命名发布；服务器不支持安全替换时拒绝发布。手动传输通过桌面宿主与 C++ 流式 worker 之间的有界本机管道转发，不经过模型或 Agent sidecar。

## 谁能做决定

React 界面通过白名单的本地宿主 IPC 请求 C++ 桌面宿主。C++ 宿主持有原生 UI 桥接、SQLite、操作系统凭据库和本地子进程；C++ SSH 服务处理已迁移的结构化远端操作，Python Agent sidecar 负责模型会话和工具提议。模型输出、远端日志、文件内容和 MCP 描述都按不可信数据处理。

Agent 工具调用须经权限引擎和宿主复核：目标由本地解析，输入、风险、任务计划和授权票据要匹配。副作用工具由目标解析、精确输入指纹、按次批准与宿主一次性票据共同约束：绑定持久任务的调用还必须匹配该任务的计划步骤，普通对话的调用则绑定本次运行、目标与完整输入。危险操作不能仅靠提示词或模型声明获得授权。用户直接输入的终端命令是单独的人工操作入口。工作树中的 `server.exec` 是独立的受控 Agent 工具，必须走上述链路，不能复用终端输入通道或让 sidecar 直接握有 SSH 凭据；仍须按施工文档验收真实目标和失败边界。

## 用户批准意味着什么

2026-11 SSH 加固的逐项变更与验收见 [SSH 安全与终端验收](./ssh-hardening-2026-11.md)。远端结果、错误、历史压缩摘要和目标完成复核使用有界、不可信数据封装。取得外部证据后提出的副作用操作须重新明确批准；`auto` 不将远端文本变成授权。交互终端没有 Agent stdin 能力，原生 worker 拒绝 AI 来源的写入；人的按键走独立入口。已消费、拒绝或过期的批准不能重放，恢复 checkpoint 不能延长原 ticket 的期限。

- `readonly` 和 `plan` 运行模式阻止 Agent 产生副作用；`goal` 才可能进入执行路径。
- `ask` 与 `auto` 是批准方式，不改变运行模式或宿主硬边界。自动批准只适用于当前用户委托且尚未依赖外部输出的首个操作；取得外部证据后的变更需要新的明确审批。自动变更后的确认回合只允许读取；扩展服务器、风险上限或操作类别要重新授权。
- 审批应显示具体服务器、操作、完整命令或足以核对的具体输入、风险和结果可能性。新的任意 shell 命令默认按高风险处理并逐条批准。目标架构允许用户对单个开发/预发布任务明确授权连续命令执行；票据绑定任务、服务器、环境、期限及调用/时长/输出预算，每次由宿主重验，不能扩到生产、未知环境或关键危险操作。命令模板只有在目标、程序和参数由宿主校验后才能降低对应调用风险；生产与关键操作仍按具体输入逐项询问。
- `server.exec` 除审批链之外还经过一份可配置的命令黑名单（`server_exec_denylist`，配置在 C++ SSH 服务 JSON 的根级和每个 target 下；根级条目由所有 target 继承，并排在该 target 自己的条目之前）。两处程序代码各自强制执行：C++ 桌面宿主在**消耗一次性批准票据之前**拒绝，C++ SSH 服务在**建立任何 SSH 连接之前**拒绝（`denied_by_policy`，HTTP 403）。它只约束 Agent 的 `server.exec`；人在自己的终端里手敲命令不受影响。条目在配置解析期校验（最多 256 条，单条模式不超过 1024 UTF-8 字节，正则必须可编译），配置有误时失败关闭，不会带着一份空名单继续启动。该名单只减不增，永远不会把一次调用变成允许。
- 拒绝或停止不会回滚已经完成的远端操作。结果未知时应进入待核对状态，不能显示“成功”。

## 凭据、数据和外部连接

SSH、Provider 与 MCP secret 交给操作系统凭据库；配置和数据库只保存必要的引用与任务元数据。跨机器复制数据库不能代替重新绑定系统凭据。主机指纹首次连接必须由用户通过可信渠道核验；指纹变化应拒绝连接并提示核查。

Python sidecar 在 `YUKINAL_DATA_DIR/agent-state/langgraph-checkpoints.sqlite` 保存 LangGraph 恢复状态，其中可能包含提示词、模型消息和工具结果。POSIX 上状态目录权限为 `0700`、数据库为 `0600`；Windows 由 sidecar 自己为 `agent-state` 目录与库文件设置**仅当前用户**的受保护 DACL（`SetNamedSecurityInfoW`，每次打开时重设），不再依赖应用数据目录的继承 ACL。检查点启用严格 msgpack 反序列化——由 sidecar 显式向 saver 注入 `JsonPlusSerializer(allowed_msgpack_modules=None)` 实现，因为 langgraph 只在导入 `langgraph.checkpoint.serde._msgpack` 时读一次 `LANGGRAPH_STRICT_MSGPACK`，任何在已导入 langgraph 之后设置的环境变量都不生效。SQLite 文件本身未加密，因此本地备份和磁盘访问也应按敏感数据保护。该存储恢复同一运行的图状态，不等同于桌面任务和计划生命周期的完整恢复。

值守运行使用独立会话，操作事件只携带运行绑定、阶段、工具名称与用量，不携带正文、参数或审批内容。只读 `watch.status` 要求当前上下文与宿主目标为同一服务器，通过 `host.context.fetch` 读取最多 20 条已保存计划的状态、时间和摘要，不返回会话正文或发起远端探测；结果仍是可能过时的不可信参考数据。前台本轮明确要求不用工具时，程序关闭工具和团队派发入口，并阻止旧目标自动续跑。

远端读取、日志、附件和 IPC 帧有大小或数量限制。MCP 响应在进入工具结果归一化前须为有效 JSON，限制为 32 层、100,000 个节点、10,000 个内容块和 4 MiB；超限、循环或无效结果会在 sidecar 内拒绝。提供给模型的内容必须受限并脱敏；审计记录应保留操作与结果的可追溯信息，避免写入凭据、完整远端正文和不必要的模型上下文。连接外部 Provider 或 MCP 服务器前，用户应知道相关数据会离开本机；MCP 自报的描述、schema 和风险注解不能单独成为授权依据。

本机↔远端的手动文件传输由用户在工作区发起。桌面宿主启动 C++ SFTP 流式 worker，并以有界 JSON-lines 帧在本机进程间转发数据；SSH/SFTP 会话留在 C++。不支持的代理、认证或信任配置明确失败，不运行 Rust SFTP 回退。原生选择/拖放授予的本机来源要绑定到短期传输句柄，远端目标绑定已核验的 `serverId` 和路径。上传/下载都要防路径穿越、符号链接越界、静默覆盖、不完整文件被当成完成；预览上限和传输上限分开。文件名、日志和预览内容仍按不可信输入显示。

## 知识索引与记忆边界

- 独立知识语料与运行时显式记忆是两个 SQLite 数据库。语料通过 `yukinal-knowledge` 管理，sidecar 以 `mode=ro` 和 `PRAGMA query_only` 打开；两者没有统一事务，语料写入不会自动同步到记忆库或对话历史。
- ACL 和 environment 是检索元数据，不是身份认证、SSH 授权或权限提升。CLI 的 `--principal` 由调用方自报，不能证明宿主身份；空 principal 只返回标记为 `public` 的文档。需要真实授权时，必须由原生宿主按已认证会话另行判定。
- 服务器对话可检索 public 全局文档及与当前服务器匹配的文档；全局对话只进入没有服务器标签的 public 文档。`forbidden_doc_ids` 只是评估断言，用来让 `eval --threshold` 在召回禁止文档时失败，不是运行时的 ACL 强制机制。
- 语料正文、标题、路径和远端相关说明都按不可信 advisory 数据处理，不能作为系统指令、工具授权或副作用批准依据。进入模型上下文的条目受数量、去重和 UTF-8 字节预算约束，并封装为不可信工具内容。
- 查询先经过本地分词，生成后的 FTS 词项和检索参数作为引用／绑定数据处理；模型文本不会直接拼成 FTS 语法。检索失败会关闭语料检索并保留显式记忆能力，不把失败伪装成空结果或可信答案。
- 桌面记忆库直接导入 Markdown/TXT 时不携带 ACL 或 environment 元数据；需要这些元数据的语料必须使用独立 CLI 建立。直接导入也不等同于服务器授权。

## 明确的限制

- SFTP 文件变更没有跨系统原子 compare-and-swap；守卫式替换会在发布前复核内容，但最终复核与原子重命名之间仍可能竞态。
- 远端命令可能在停止或断线前已被服务器接受；退出码未知时需核对实际状态，不得自动重试非幂等操作。
- 模型结论不能替代人对生产变更的判断；服务器、MCP 或模型服务也可能在调用后才失败。
- 应用退出时不承诺后台巡检继续运行；停止 sidecar 不保证撤销外部系统已接受的操作。
- `server.exec` 命令黑名单是纵深防御护栏，**不是沙箱**：匹配只发生在原始命令字符串上（仅做空白归一化，可选大小写不敏感），不做任何 shell 展开，因此 `r''m`、`$IFS`、base64 管道、引号拼接等混淆写法可以绕过它；它绝不替代审批流程，也不能被当作“命令已被证明安全”的依据。另注：在预配置的常驻服务上，被黑名单拒绝的 `server.exec` 调用仍会消耗该 target 的一次性授权槽位（`http_service.cpp` 的槽位消耗先于策略检查），因此同一 target 之后的 `server.exec` 会被 409 拒绝；桌面宿主路径不受影响，因为宿主在消耗票据之前就已拒绝、请求根本不会到达服务。
- 安装包当前未签名，真实安装与真实端点的验收状态见[交付与发布](./release.md)。
