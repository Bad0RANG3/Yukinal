# 文档

仓库根的 `README.md` 只做一件事：介绍项目 —— 它是什么、现在能做什么、怎么跑起来。**规则、约束与决策在这里**，因为它们的读者是改代码的人：写进这个目录的东西要么约束两个以上模块，要么是一份改错了不会立刻报错的契约。

## 阅读顺序

- **想知道现在能做什么、还差什么**：根目录的 [项目状态](../README.md#项目状态) 与 [今天真正可用的能力](../README.md#今天真正可用的能力)；缺口以 [当前限制](./limitations.md#当前限制) 为准，它是**全部**已知缺口的唯一来源。
- **想理解整个项目**：先读 [执行与授权模型](./execution-model.md#执行与授权模型)（这是整个项目的重点），再读 [架构总览](./architecture.md#架构总览)。
- **要动手改**：先在 [仓库地图](./architecture.md#仓库地图) 里定位到层，再读那一层的边界文档 —— [模型 Provider](./boundaries/provider.md#边界模型-provider)、[外部工具（MCP）](./boundaries/mcp.md#边界外部工具mcp)、[Markdown 渲染](./boundaries/markdown.md#agent-回复的-markdown-渲染)。
- **要动权限**：三档各自一份 —— [read](./risk-tiers/read.md)、[write](./risk-tiers/write.md)、[dangerous](./risk-tiers/dangerous.md)。
- **想知道某个形状是为什么**：[架构决策记录](./adr.md#架构决策记录adr-00010015)。代码注释里的 `ADR NNNN` 指的就是那里。

## 写进这里的内容需要满足至少一条

- 它约束**两个以上模块**，读者无法只读一份代码就理解全貌（例如「Docker 工具名如何在 Provider 边界变形」）。
- 它是一个**公开契约**，改动会让另一侧编译或运行失败（例如 Tauri IPC 命令表、sidecar 的 JSON-RPC 方法名）。
- 它属于**安全模型**，行为是否正确无法只靠单侧测试判断（例如「谁能生成执行票据」）。
- 它解释**为什么是这个形状**，而这个理由在代码里只能看到结果、看不到权衡。

留在代码里的内容：某个函数、某个常量、某条正则为什么这样写，写在它旁边；一次性的排查结论、临时开关、尚未落地的想法不进文档，那会让读者把「打算做」误读成「已经做」；复述类型的字段清单也不进文档，类型本身就是契约，重复一遍只会产生两份会漂移的真相。

一条硬规则：**文档里写的每一句话都必须能在仓库里找到对应的实现或测试。** 如果某个能力只完成了一半，就写清楚哪一半完成了；不要用「支持 X」这种无法验证的措辞盖过去。

GitHub 与社区协作必须能在仓库根目录直接发现的文件保持为独立入口；它们不重复技术规则，只负责说明如何参与、如何报告问题和如何联系维护者。

## 维护这些文档的规则

- **根 `README.md` 只介绍项目，不写规则。** 规则、约束与决策写进这个目录，一篇文档回答一类问题。新增内容时先看它属不属于已有文档（比如「审计落库」属于 [安全与数据边界](./security.md#agent-能碰什么)，不该新建文件），确有必要才新建，并**同时**更新根 `README.md` 的文档表与上表。
- 目录只有两层：`docs/*.md`，加上两个有理由的子目录 —— `docs/boundaries/`（三个跨模块边界）与 `docs/risk-tiers/`（三档权限规则）。不要再加深一层，也不要为某个模块、某条决定或某次发布在别处新建 markdown。
- 文档的一级标题是它自己的名字，节标题用二级标题，别把 `**加粗**` 当节标题用：那不会产生锚点，链接就没法指过去。
- **新增一条决策**时，在[架构决策记录](./adr.md#架构决策记录adr-00010015)末尾加一条，编号取下一个四位零填充数字，并保持既有的三栏结构：决定、为什么、代价。**已有记录不应被改写来掩盖变化**：决定变了就新增一条，并在旧记录的状态里标明被哪一条取代。
- 每条决策记录都必须写清**代价**。一个没有代价的决定，读者无法判断它是不是被想过。
- 文档之间的相对链接必须指向仓库里真实存在的文件，锚点也必须真的存在：`node scripts/check-docs-links.mjs` 逐个核对（它先剥掉代码围栏与行内代码，并带正负对照，所以「一个链接都没读到」不会被报成通过）。用词由 `node scripts/check-publication.mjs` 检查（禁止引用未发布的内部材料，公开标准的编号是例外）。
- 功能范围变化时，**同时**更新[今天真正可用的能力](../README.md#今天真正可用的能力)、相应的边界文档，以及[当前限制](./limitations.md#当前限制)。缺口被补上时，把它从[当前限制](./limitations.md#当前限制)里**删掉**而不是标记为已完成——那一节只列现在做不到的事。
- 可验证性是硬要求：不要写「支持 X」而仓库里找不到实现或测试。
