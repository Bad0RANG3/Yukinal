# 当前限制

这一节是**全部**已知缺口的唯一来源：每条都写明现在做不到什么、以及为什么。已经做完的能力见 [版本与发布历史](./changelog.md#版本与发布历史)；有意为之、不会被“补完”的安全边界在下一节。

- **Agent 的副作用入口现在必须绑定完整的 durable task/ChangePlan。** `filesystem.write`、`filesystem.edit`、备份/恢复、重启、包安装和 `mcp.*` 在 sidecar registry 与 Rust 宿主两层都要求 `taskId`、`planId`、`planStepId`；普通聊天即使伪造自动票据也会在执行前失败关闭。交互式终端不属于 Agent 工具目录，仍是用户明确操作的人工旁路，不提供自动化接口，也不伪装成任务审计中的 Agent 步骤。这个门槛只在本地、fixture、stdio 与 `127.0.0.1` 路径验收，未把真实外部维护环境写成已验证能力。
- **会话授权只覆盖被批准的精确输入。** Permission Engine 将规范化后的工具输入保存为 SHA-256 指纹，registry 会拒绝把同一工具/目标的票据重放到另一个路径、容器、服务或包版本；指纹不是原文，也不能证明远端状态没有在批准后变化。

- **安装包只在 Windows 上构建过，也没有做过安装后启动验收。** `pnpm package` 在本机产出了 NSIS 安装程序与 WiX `.msi`（见 [打包与分发](./packaging.md#打包与分发)），但尚未真的安装并启动；macOS 的 `.app`/`.dmg` 与 Linux 的 `.deb`/`.rpm`/`.AppImage` 仍未在对应平台构建。CI 已有三平台打包作业，这只证明配置存在，不替代真实产物验证。
- **没有代码签名、公证与自动更新。** 未签名的 Windows/macOS 包会触发系统警告；没有更新通道，升级靠用户重新下载。
- **仍需用户自己准备 Node.js ≥ 24。** 安装包不内含、不下载、不缓存运行时。正常启动与 `YUKINAL_NODE` 路径会在 sidecar 启动前执行有 5 秒上限的 `node --version` 预检，缺失与过旧都会给出可操作错误；`YUKINAL_AGENT_COMMAND` 被明确视为自定义程序，拥有自己的运行时契约，因此刻意不做 Node 版本探测。
- **`.deb` / `.rpm` 已声明基线运行时依赖，但尚未在干净发行版中安装验证。** 配置包含 WebKitGTK 与 GTK 的常见备选包名；不同发行版的真实包名和版本仍可能不同，因此不能把“打包器接受配置”说成“各发行版都装得上”。
- **MCP Streamable HTTP 支持静态头、两种 OAuth 流程与客户端密钥，但还不是完整的动态认证矩阵。** HTTP 会完成 `Mcp-Session-Id` 会话、JSON/SSE 回包、GET 事件流、取消通知与 DELETE 终止；设置页可为 endpoint 配置最多 32 条有序静态认证头。OAuth 支持手填 issuer，也会从 `WWW-Authenticate` 或 RFC 9728 protected-resource metadata 自动发现授权服务器，然后使用 RFC 8414 discovery、`resource` 参数与 refresh token；每个 endpoint 可选一条流程：authorization code + PKCE S256（随机 loopback callback），或 RFC 8628 device code —— 后者不需要本地回调，界面会显示授权服务器给的 `user_code`、优先打开 `verification_uri_complete`，并按服务器给的 `interval` 轮询，`authorization_pending` 与 `slow_down`（间隔 +5 秒）都只是继续等待，`access_denied`、`expired_token`、`expires_in` 到期与用户取消各自结束并给出各自的原因。轮询就在那个等待中的请求里，没有后台任务：取消或 `expires_in` 到期都会结束它，轮询次数另有硬上限，所以即使等待它的窗口已经不在了，它也不会活得比 `expires_in` 更久。客户端认证三选一：`none`（公共客户端，只发送 client id）、`client_secret_post`（密钥作为表单参数）或 `client_secret_basic`（`Authorization: Basic`，且请求体里不再重复凭据）；密钥只进系统凭据库，配置里只有引用，设置响应、错误与 Debug 输出里都没有它，留空表示保留、重填表示轮换、换认证方式或删除服务器会回收它，且换方式后必须重新填写。client id 可手填，留空时使用 RFC 7591 dynamic client registration 注册 `token_endpoint_auth_method: none` 的公共客户端（device code 流程注册 device grant，不带 `redirect_uris`）；服务端若在注册响应里返回 secret，连接会明确拒绝而不是改用它。token bundle 只进系统凭据库，过期前自动刷新，401 会强制刷新并仅重试一次；改动 issuer、client id、scopes、流程或客户端认证方式都会让已存令牌失效并要求重新授权 —— 这些都是身份，不是显示偏好。发送方约束令牌（DPoP，RFC 9449）已经是**可选项**：开启后每台服务器一把 Ed25519 私钥（只进系统凭据库），每个请求带一个绑定方法与 URL 的 proof（`ath` 绑定令牌、`jti` 每次重随机），服务器可以用 `DPoP-Nonce` 挑战，`token_type` 必须是 `DPoP`，密钥丢失只能重新授权。它默认关闭，而且只有服务器真的验证 proof 时才有意义 —— 不验证的服务器只是多收一个头。仍然没有的是**自定义的按请求动态签名**（协议未定，见 P1-2）。应用级出站网络设置默认直连，也可以显式选择系统代理；它按 `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY`（大小写都认）以及 Windows 当前用户 Internet Settings、macOS `scutil --proxy` 读取静态代理，Linux 只认环境变量，不执行 PAC；`NO_PROXY`/`ProxyOverride` 交给 HTTP 客户端匹配，代理凭据只存在系统凭据库且只支持 Basic。改动在下一次连接生效，代理错误会标明来源。远程 endpoint 必须使用 HTTPS，明文 HTTP 只允许回环地址，URL 不接受内嵌凭据、查询参数或 fragment，重定向也不会被跟随。
- **MCP 工具默认一律按 `critical` 处理，只有用户显式信任某台服务器才会按注解降级。** 服务器自己的风险注解默认不被采信，所以每个 MCP 工具默认在任何运行模式下都要逐项批准，会话授权也不能记住它。用户在设置页为某台服务器开启「信任此服务器声明的只读/破坏性注解」后（[ADR 0074](./adr.md#adr-0074mcp-注解按服务器显式信任宿主映射有效风险)），宿主才把该服务器自述的 `readOnlyHint === true` 映射为 `low`、`destructiveHint === false` 映射为 `medium`，其余（含缺省、类型错误、其它情况）仍是 `high`；`annotationTrust` 为 `none` 时无论注解是什么都仍是 `critical`。注解类型不对或缺失按“未声明”处理，不会让整个工具导入失败。代价很直接：默认情况下一个只读的外部工具也要点一次；开启信任等于允许这台服务器用自己的说法降低自己的档位，只应对确实信任的服务器开启。
- **MCP 取消是标准通知，不是回滚。** 宿主会发送 `notifications/cancelled` 并停止等待，但协议允许服务器忽略通知；已经发生或仍在进行的副作用无法撤回。
- **Agent 停止确认也是运行栅栏，不是远端回滚。** `agent.run.stop` 的 `stopped: true` 会让宿主立即封存 durable run、任务和调度记录，并挡住迟到事件；如果某个远端写入已经越过目标系统的提交点，停止不能把它撤销，必须通过新的只读核对、基线和独立回退计划处理。
- **停止/恢复的跨层验收仍是离线状态核心，不是完整运行时验收。** 桌面 Rust 单测会在同一 `AppState` fixture 中串起事件状态同步、run 持久化、取消收口、活动 run 栅栏和迟到终态拒绝；它能证明 SQLite 状态机的边界，但没有启动真实 Tauri 窗口、sidecar 进程或远端部署，因此不能排除 IPC 时序、进程退出或网络断开期间的额外问题。
- **真实 MCP 互操作验证仍只是抽样。** 2026-09-15 已实际跑过官方 `@modelcontextprotocol/server-everything` 的 Streamable HTTP、官方 TypeScript SDK 的 JSON 回包模式，以及独立 DuckDuckGo / Fetch server 的 stdio；握手、工具目录、echo 调用、JSON/SSE、GET stream 与 DELETE 都有记录，但独立 server 的上游反爬/SSRF 错误也会如实保留。验证需要网络、通过环境变量显式启用，不能替代对所有第三方实现的兼容保证。
- **Agent 的 `server.logs` / `server.services` 仍是受限远程读取，不是完整日志平台。** `server.logs` 现在可以在 `journalctl` 上按最多 7 天的 `sinceSeconds` 和一个安全的 `.service` unit 查询；如果目标只能提供 syslog/messages，宿主会拒绝带过滤条件的请求，避免把未过滤的尾部伪装成查询结果。`server.services` 可以按精确服务/容器名和 normalized state 在有界清单上筛选。两个工具仍只返回宿主固定命令产生的有界结果（日志最多 500 行）；不可用的日志/服务管理器会返回结构化的 unavailable 结果，不会猜测。它们已接入任务证据和计划 fence，但没有历史索引、任意日志查询或真实外部主机部署验收。
- **`investigation.evidence.triage` 只是候选信号整理，不是根因分析器。** 它最多取回 32 条当前任务中已脱敏的证据，在 sidecar 内按固定规则统计高资源使用、服务/容器异常、日志模式和截断/采集失败，并在至少两条不同证据共同命中有限信号族时返回交叉候选；所有结果仍是低/中置信度，不返回新的现场正文、不理解拓扑或业务指标、不创建 evidence、不推进计划，也不会授权写入。模型仍须引用原始证据并重新采样，真实外部目标尚未用该工具验证。
- **两套原生 Provider 适配器从未对真实 API 调用过。** 翻译逻辑、流式状态、取消与错误路径都是照协议文档写的、用假响应测的。每个适配器的假设列在 [模型 Provider](./boundaries/provider.md#边界模型-provider) 里。
- **Host certificate KRL 支持签名，但信任集合仍是本地静态配置。** 可配置受信 CA、有效期、principal、本地路径或 HTTPS URL，以及最多 16 把独立 KRL 签名公钥；客户端会拒绝被序列号、key ID、CA/公钥或 SHA-1/SHA-256 指纹撤销的 host certificate。`KRL_SECTION_SIGNATURE` 必须位于末尾，每一条签名都要有效，且至少一条要由 host CA 或配置的独立 signer 验证通过；同时列出旧、新 signer 即可完成轮换。在线 URL 禁止内嵌凭据、query、fragment 与重定向，下载上限 16 MiB，按应用级网络设置连接（默认直连），失败时拒绝连接。未知关键扩展仍失败关闭；下载源不使用认证头、不执行 PAC，是否走代理由应用网络设置决定，签名者列表也不会远程自动更新。
- **`filesystem.edit` 有守卫，但仍不是 compare-and-swap；备份与恢复也有明确边界**（[ADR 0017](./adr.md#adr-0017filesystemedit-的替换阶段有守卫但仍不是-compare-and-swap)、[ADR 0043](./adr.md#adr-0043文件备份与守卫恢复只由宿主决定路径)）。普通文件走同目录 staging → 守卫复核 → rename → 发布复核，读者不会看到半写状态；没有 SFTP compare-and-swap，所以检查与 rename 之间仍有一个窗口，只是它被缩到「读取后的 `stat` → rename」这一段，并且这一段里的改动会变成一条**并发修改错误**而不是静默覆盖。**同一秒内、同样大小的改写仍然无法区分**（SFTP 的 mtime 粒度是秒）。symlink、`nlink > 1` 的硬链接、以及远端不报告链接数（没有可用的 `stat`，例如 Windows 上的 OpenSSH）都会明确拒绝，而不是换成原位写；服务器拒绝 rename、staging 建不出来、或 `mode`/`mtime`/`owner`/`group` 有一项保不住时同样拒绝，错误里点名是哪一项。ACL 与 xattr 既不能保留也无法通过 SFTP v3 检测，所以不在这条工具的承诺范围内；需要保住它们的文件不该用它。`filesystem.backup` 只复制不超过 1 MiB 的普通单链接文件到宿主生成的同目录、独占新路径，拒绝任意 destination、符号链接、硬链接和读写期间的 stat 漂移（编辑与整文件写入仍各限 512 KiB）；宿主还会把成功的备份以服务器、目标路径、revision、任务归属和 `available/restored` 状态写入 SQLite，远端原文不会落库；`filesystem.restore` 只接受账本中同一目标、同一任务（或同一无任务会话）的可用备份和当前 `expectedRevision`，用高风险、逐项审批和原子替换发布，并在成功后消费该记录。终态任务的证据与阶段工件现在可以在任务页先预览再显式清理，宿主会保护所有历史引用；远端文件备份不会被这条本地清理路径自动删除或轮换，验证失败也不会自动回退。
- **受限 auto 与远端备份仍有明确边界。** 只有远程开发/预发布的 `goal + execute` 任务可以让 medium 风险的配置备份、编辑与整文件写入（含“先备份再写入/编辑”的组合）action 免逐项点击，并且宿主会复核任务权限与目标；`filesystem.restore`、`backup_cleanup`、重启和包安装仍需逐项批准。`filesystem.backup.list` 只能让当前任务读取宿主账本的 bounded metadata，不检查远端文件是否还存在；只读的 `filesystem.backup.retention` 会跨任务盘点同一服务器的可用备份（按原路径分组，`keepLatest` 与 `olderThanDays` 取交集，候选最多 32），但不删除也不访问远端；`backup_rotation` playbook 把精确的 items 变成一个 `requiresApproval: true` 的 `filesystem.backup.cleanup` 批量步骤，用户批准后宿主逐项重新读账本、远端复核再删除，部分成功会带 `partial: true`。跨任务删除只在批量模式且该项被已批准计划步骤绑定时允许；单项清理仍限同一任务。**后台自动清理、定时轮换、真实外部主机验证仍未完成**（[ADR 0076](./adr.md#adr-0076备份保留策略与跨任务批量清理始终逐步骤审批无后台删除)）。
- **playbook 的 observation window 只延长最终只读验证。** `investigation.playbook` 可以声明有界的持续时间、采样间隔、成功条件和最终验证工具；sidecar 会拒绝超出最终验证步骤的工具，收到宿主的下一次采样时间后只在同一运行内重放完全相同的验证读取，宿主拥有样本计数、截止时间和异常收口。运行预算耗尽或 sidecar 重启不会在后台复活窗口；它不会自动重试写入、回退或扩大目标范围，也没有把“窗口完成”验证成真实外部部署稳定性；当前验收仍只覆盖本地 fixture、SQLite、stdio 和回环路径。
- **任务 guardrails 是有界的词法门控，不是远端策略引擎。** 用户可以给任务设置最多 1095 天（3 年）跨度的 UTC `notBeforeAt`/`expiresAt`、各最多 128 项的精确内部工具名黑名单和绝对路径前缀黑名单。宿主会在启动、`plan.check` 和实际 `host.tool.execute` 前拒绝越界请求；持久化调度器也会在启动 sidecar 前复核时间窗，把窗口外触发记录为 `skipped/outside_time_window`，不消耗 Provider 或 Agent 运行。路径会按 `.`/`..` 做词法归一化；它不能证明远端 symlink、挂载或业务权限没有把路径映射到别处，也不会在应用退出期间替用户继续执行。旧任务的空 guardrails 只表示没有额外任务级限制，Permission Engine、目标范围和危险动作审批仍然有效。
- **auto 失败恢复依赖桌面任务页保持打开。** 当前 UI 只会对 retryable transport/timeout 失败调用一次宿主恢复事务，并按 `maxAttempts` 重新启动；应用完全退出时不会在后台偷偷复活任务，用户下次打开任务页后仍可看到失败并手动恢复。恢复不重放旧计划、审批或基线。
- **持续巡检的重启恢复仍依赖桌面进程重新启动。** 应用启动时会在 SQLite 事务中封存旧的 schedule/durable run、关闭未完成步骤并清除死 `activeRunId`，下一次到期才会重新采集；claim 不会覆盖上一轮终态比较结果。它不是独立系统服务，应用完全退出期间不会在后台补跑，也不代表真实外部目标已经完成验证。
- **证据去重只发生在同一 durable run 的落库边界。** 宿主会为完全相同的任务/范围/来源/输入/内容类型/内容哈希/截断状态复用已有 `evidenceId`，跨 run 不合并，避免破坏持续巡检的样本比较；计划证据步骤命中 `reused: true` 时会失败关闭、不生成新的基线工件并要求重规划或等待用户。绑定到同一计划步骤的 server/docker/systemd/package/filesystem 只读调用还会在宿主真正执行前按逻辑动作指纹返回 `duplicate_call`，避免同一个计划样本再次到达远端；运行中的 observation window 验证步骤由宿主的采样间隔和截止时间控制重复样本，普通聊天读取、非宿主工具和换新计划的重采样仍不受这条 fence 约束，因此它不能替代全局采样节流或语义级排查规划。
- **多模态输入支持图片、PDF、UTF-8 文本文件与音频，尚不支持任意二进制文件。** 图片可输入 PNG、JPEG、WebP 与 GIF，单张原图最多 5 MiB，且最多 8 张；PDF 可输入有效 `%PDF-` 文件，单文件最多 8 MiB，最多 4 个；音频可输入 WAV、MP3、OGG 与 FLAC（同样按**魔数**校验，不看扩展名），单段最多 8 MiB，最多 4 段；图片、PDF 与音频的原始字节**共用**一个 12 MiB 总预算，base64 展开后仍须留在 sidecar 的 24 MiB 单帧上限内（MCP 帧上限保持 8 MiB）。文本文件必须是有效 UTF-8、无二进制控制字符，单文件最多 512 KiB、总计最多 2 MiB、最多 8 个；它们会作为明确分隔的文本块发送。图片与 PDF 分别映射到三家 Provider 各自的原生内容块，音频映射为 OpenAI 的 `input_audio`（只接受 WAV/MP3，其它格式会明确失败而不是被丢掉）与 Gemini 的 `inlineData`；**Anthropic Messages 没有音频内容块，因此带音频的请求会直接失败并说明原因**，而不是静默省略。**这两条 Provider 映射都还没有对真实 API 验证过**（与两个原生适配器整体一样），模型是否接受某种输入仍由上游决定，当前模型目录不声明视觉、PDF 或音频能力。
- **Markdown 仍不是 CommonMark，而且实测数字已经写下来了。** 对照的规范版本固定为 **CommonMark 0.31.2**；官方 652 个例子里有 189 个被显式排除（它们是三条有意偏差的领域：HTML 按纯文本、链接只认 `http(s)`/`mailto`/页内锚点、远程图片在用户同意前不加载），剩下的 **463 个里 434 个与规范文本完全一致、461 个没有丢字**（测量方法、排除规则、逐节表格与运行方式见 [Markdown 渲染](./boundaries/markdown.md#与-commonmark-0312-的差距实测2026-09-15)）。还丢字的只剩 **2 个例子，而且是有意的偏差**：`&copy;`、`&quot;` 这类**命名**实体引用按字面显示。数字引用（`&#35;`、`&#x22;`）已经实现，命名引用要一张 2231 条的 HTML5 名字表，与「不为小功能引大依赖」冲突，所以不从。其余语法缺口（强调的 delimiter run 规则、列表项缩进、跨行代码 span、容器里的 lazy continuation）已经按规范补齐。未知语法按纯文本保留（这会显示多余的标记字符，但不允许丢内容），门禁用 `apps/desktop/tests/markdown-spec.test.ts` 的逐节下限挡住回归：数字只能变好，范围（每节例子数）要改必须重新基线。

- **持续巡检的 UI 控制已接通现有宿主契约。** 任务页可以修改宿主允许范围内的间隔和通知策略，也可以暂停、恢复或撤销触发器；撤销是终态，不能在 UI 中重新激活。这里仍然不是独立系统服务：应用完全退出时不会后台补跑，间隔变更也不会扩大任务预算或只读权限。
- **持续巡检的固定基线仍依赖本地证据保留。** 用户可以把同一 schedule 下带证据的成功运行设为比较基线；如果之后按保留策略清理了这轮证据，宿主会报告 `insufficient_evidence`，不会偷偷改用最近一轮。没有固定基线的旧 schedule 仍比较最近成功样本；基线选择、清理和比较都只在本地 SQLite/fixture 中验收，未证明外部目标长期观测的完整性。

### 有意为之的边界（不是待办）

下面这些看起来像限制，其实是安全模型的形状。它们不会被“补完”，改动它们等于改动授权模型本身（[ADR 0005](./adr.md#adr-0005permission-engine-是唯一的执行授权决策者)、[ADR 0009](./adr.md#adr-0009agent-权限采用显式的运行级委托)、[ADR 0072](./adr.md#adr-0072high-动作可记住到本次运行限定远程开发与预发布)）。

- **危险动作按档位与目标逐项批准；只有远程开发/预发布的 `high` 动作可以记住到本次运行。** `filesystem.restore`、`docker.restart`、`systemd.restart` 和 `package.install` 声明为 `high` 风险。根据 ADR 0072，用户在远程 development/staging 目标上对一个精确的 high 动作点“本次运行批准”后，同一工具 + 同一目标 + 同一输入指纹在本次运行内不再询问；`critical`（MCP 等无法界定副作用的动作）以及生产、未知、本机目标上的 dangerous 档位仍然每次都要单独批准。这不是“总是允许”：授权仍是一次真实的用户点击，绑定输入指纹，只在本次运行有效，运行结束即清除（[权限档位：dangerous](./risk-tiers/dangerous.md)、[ADR 0072](./adr.md#adr-0072high-动作可记住到本次运行限定远程开发与预发布)）。代价很具体：一次长任务里对同一容器或服务的完全相同重启不再每次打断，但批准一次后同一指纹动作在本次运行内不再可见地确认；生产环境无论如何都不会被静默记住。systemd playbook 只接受 `.service` unit，包 playbook 只接受 apt/dnf 和白名单包引用；文件备份和备份清理是受限的 medium-risk 动作，自动回退、自动清理和任意命令仍不提供。
- **浏览器预览里没有原生能力。** 在浏览器里打开 Web 前端只能看到界面骨架：终端、远程文件、日志、服务、活动、对话历史和本地数据库都需要 Tauri 桌面应用，因为它们全都走 Tauri 命令与原生侧（SSH、PTY、keychain、SQLite）。这是有意的：WebView 不该持有进程句柄，也不该在它的生命周期里决定一个进程的生死（[ADR 0001](./adr.md#adr-0001agent-runtime-作为独立-nodejs-sidecar由-rust-拥有其生命周期)、[ADR 0008](./adr.md#adr-0008rust-负责-sidecar-的启动握手监督与回收)）。代价是：预览只能用来调样式与布局，任何真实操作——包括所有手工验收——都必须在 Tauri 窗口里做。
- **跨语言运行时验收的边界。** Rust supervisor 现在有一条真实启动打包 Node sidecar、回环 Provider SSE、host tool/evidence RPC 和完成事件的离线验收；它仍不是 Tauri IPC、真实 Provider、SSH 主机或远端部署验证。不能把这条回环路径描述成外部网络能力。
- **资源生命周期只完成本地和回环验收，尚未覆盖生产资源曲线。** `Arc` 保活、MCP HTTP 最后句柄释放、sidecar/MCP supervisor、终端 forwarder、SSH keepalive，以及 Collector 的本地进程组取消和 SSH 命令取消都有本地回归；WSL 的 `127.0.0.1:22222` OpenSSH 已验证密码、明文/加密私钥、用户证书、ssh-agent、保活、超时、取消和主机指纹阻塞。Tauri 退出也只在 WSL/Xvfb 单次冒烟中检查了应用与 sidecar 收口。未验收的是公网 SSH 主机、真实断线与重连、第三方 MCP 取消、Provider 连接复用、Windows 原生进程终止、安装包启动，以及反复开关窗口、MCP、PTY、SSH 和 sidecar 后长时间的内存、线程、文件描述符与子进程曲线；这些结果不能从回环测试外推。
